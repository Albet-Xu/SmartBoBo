## 尝试过的方案
- ❌ 方案: requests 直接 POST /m-base/customize/main/home，body 直接给明文 JSON → fail，原因: 返回 {"res":"<base64>"} 或错误，必须加密

- ❌ 方案: 把 wbsk_Wbox.js 的 writeSegment(offset, base64) 数据段全部解出来，重建 500KB wasm 内存镜像，搜 AES/DES/SM4/MD5/SHA 常数 → fail，原因: 内存里没有任何标准密码学常数；内存 402432/402800 是两段 360 字符十六进制串（解成 180 字节密钥容器），AES-128/192/256 密钥排程全部对不上（44/52/60 words），说明算法被改造，纯 Python/JS 复刻不划算
- ❌ 方案: 用浏览器当 oracle 取明文/密文向量（wbsk_AES_cbc_encrypt_base64('0123456789abcdef', y)），再用 cryptography 暴力试 AES-128/192/256 × 多种 key/IV 组合（y、k 常量、内存密钥段、大小端） → fail，原因: 全部不匹配，确认不是标准 AES

## 经验总结（正向）
- 遇到『函数名叫 AES 但内存里找不到任何标准密码学常数』的 wasm/wasm2js 加密，别硬啃算法：先判断是不是 Emscripten wasm2js（特征：文件里 var WebAssembly = {...} polyfill + writeSegment(offset, base64) 写数据段 + wasm2js/asm2wasm 注释），是的话直接把官方 JS 存本地在 Node vm 里跑，字节级一致且零复刻成本 —— 这正是 xishandong/crawlProject『进阶篇/js逆向/wasm』一类案例的通用打法
- wasm2js 模块在 Node 里跑通的两个关键：补齐 document/location/navigator/XMLHttpRequest/fetch 等浏览器占位对象；run() 是异步的（addRunDependency('wasm-instantiate')），必须轮询 typeof calledRun!=='undefined' && calledRun && Module.asm 等运行时 ready 再调用，否则报 'you need to wait for the runtime to be ready'
- 常驻 Node 子进程 + stdin 逐行 JSON 协议，比每次请求 spawn 一个 node（要重新加载 917KB 模块）快得多
- 一定要留浏览器实测自检向量（明文→密文）并在脚本里 selftest：CDN 一改版就能立刻发现，而不是采集出一堆垃圾数据
- camoufox-debug 的 debug_evaluate 可能跑在隔离世界（Object.keys(window).length===0 就是信号），拿不到页面全局变量；此时改用 js-reverse 的 evaluate_script(mainWorld=true)
- 接口请求体是加密的，但可以直接把抓到的密文用同一套解密函数解出来 —— 拿到的是浏览器真实发的业务参数，比自己猜 payload 靠谱得多（notices 少传 type/platformType/showType 就返回 ERR0000）
- 服务端 JSON 键序可能不固定（Java HashMap 信封），增量指纹必须 json.dumps(..., sort_keys=True) 规范化键序，否则顺序抖动会被误判为内容更新

## 教训总结（负向）
- 不要在业务 bundle 里死找加密实现：关键字只能搜到调用点（wbsk_AES_cbc_encrypt_base64 + 固定 IV 常量），算法在另一个 wasm 文件里
- 不要因为函数名带 AES 就假设是标准 AES：先验证密钥排程（AES-128=176B/192=208B/256=240B words 递推）。这里 180 字节密钥容器三种长度都不匹配、内存无 sbox，说明是改造算法，及时止损
- 不要试图下载 wbsk_Wbox.wasm：CDN 上 404，wasm 已内联进 wasm2js 的 JS 里，白折腾
- 增量采集不做易变字段剔除 = 每次全量重抓：transactionId/servertime/ConsumeTime/StartTime/EndTime/accessToken 必须剔除；ceair 的 promotion 接口把带 transactionId 的深链 JSON 塞在 action 字符串里，需要单独归一化
- 别照抄浏览器全部风控头（同盾/阿里云 ssxmod）：实测最小头 + 正确 Cookie + 正确加密体即可通过，堆头反而可能触发更严风控
