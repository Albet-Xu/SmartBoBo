# SmartBoBo 项目框架说明

> 面向项目维护者与使用者，从整体框架、模块职责到两大核心工作流（采集模式、工作流模式）的运行方式给出系统说明。
> 部署与日常启动见根目录《部署说明.md》《启动说明.md》；各功能实现细节见 `docs/说明文档/功能实现/`。

---

## 1. 项目概述

SmartBoBo（BoBo）是一个**本地智能采集平台**，基于 DeepSeek Harness（dsh）构建，把"网页采集 / 逆向 / 入库"封装成**对话式 Agent**：用户在浏览器里和智能体聊天，智能体调用本地真实浏览器引擎抓取网页、把内容落盘到本地，甚至按用户要求清洗后写入其指定的数据库表。

平台通过 **Agent 预设（preset）**系统提供多种"模式"，每种模式是一份 persona 提示词 + 一套工具集的组合，让同一个 dsh 底座针对不同任务目标呈现出差异化行为。

**已实现的模式**（按 `order` 排序）：

| order | 模式 | 定位 |
| --- | --- | --- |
| 1 | 标准模式 | 通用助手 |
| 2 | code | 编程助手 |
| 3 | 极简 minimal | 精简对话 |
| 4 | cordis | 插件调试 |
| 5 | 采集模式 crawl | 只做网页采集落盘 |
| 6 | 逆向模式 reverse | 网页逆向 + 生成爬虫脚本 |
| 7 | 工作流模式 workflow | 采集 → 确认字段 → 提取入库 |

## 2. 整体架构

SmartBoBo 属于**前端会话 + 本地插件编排 + 本地 Python 引擎**的分层架构，全程依赖本地运行，数据不出本机。

```
┌──────────────────────────── 浏览器（Web 端 http://127.0.0.1:7070）────────────────────────────┐
│  左侧导航栏：会话 / 工作区 / 搜索 / ★数据库(DBX)；设置 → Agent 预设（切换模式）                          │
└──────────────────────────────────────────┬─────────────────────────────────────────────────────┘
                                            │ HTTP / WebSocket
┌──────────────────────────────────────────▼─────────────────────────────────────────────────────┐
│                         dsh 运行时（Node.js + pnpm workspace，DeepSeek Harness）                    │
│   插件式架构（Cordis）：一切皆插件                                                                      │
│   ├─ preset 系统    —— 按 order 扫描 agent-presets/，装配 persona + 工具集                         │
│   ├─ persona 插件   —— @deepseek-ai/dsh-persona：把模式行为规则注入 system prompt                  │
│   ├─ 采集工具插件   —— @deepseek-ai/dsh-tool-acquisition：注册 crawl_fetch 工具（编排层）           │
│   ├─ 通用工具集     —— shell(pwsh/bash)、fs、ask-user、web、skill、subagent、workflow 等            │
│   ├─ MCP 客户端     —— @deepseek-ai/dsh-mcp-client：挂载 js-reverse 等网页逆向 MCP                  │
│   └─ 技能库         —— skill-filesystem 扫描 ~/.dsh/skills/，工具模板技能即时可用                    │
└──────────────────────────────────────────┬─────────────────────────────────────────────────────┘
                                            │ 调用 python 脚本 / 读取 dbx.db
                    ┌───────────────────────┴────────────────────────────┐
                    ▼                                                    ▼
┌────────────────────────────┐                  ┌───────────────────────────────┐
│  Python 采集引擎（.venv）      │                  │  DBX 数据库运行时（本地独立服务）    │
│  engines/{camoufox,scrapling,│  采集结果落盘      │  dbx-runtime/dbx-web.exe        │
│  crawl4ai}                   │ ──────────────►   │  http://localhost:4224         │
│  scripts/run_*.py            │  当前工作区 data/  │  连接配置存 dbx-runtime/data/    │
└────────────────────────────┘                  └───────────────────────────────┘
```

**三大层次职责**

1. **会话与交互层（浏览器 + dsh）**：用户对话、模式切换、工具调用展示、审批交互（写库等副作用前的确认）。
2. **编排层（dsh 插件）**：persona 提示词决定"做什么、怎么做"；工具集决定"能用什么工具"；`tool-acquisition` 是采集的 Node 编排入口。
3. **执行层（Python / DBX）**：真实抓取网页、转 Markdown 落盘；`dbx_connector` 连库、`extraction_template` 生成提取脚本做 UPSERT 入库。

**关键目录结构**

```
SmartBoBo/
├── dsh/                              # DeepSeek Harness（Node pnpm monorepo）
│   ├── apps/cli/config/agent-presets/ # ★ 各模式预设：{standard,crawl,reverse,workflow,...}/{preset.yml, agent.cordis.yml}
│   ├── packages/acquisition/tool-acquisition/  # ★ crawl_fetch 采集工具插件
│   ├── packages/client/               # Web 前端（含"数据库"入口、品牌替换）
│   └── patch/                         # web-acquisition.yml 等装配补丁
├── scripts/                          # ★ Python 采集脚本 run_camoufox/run_scrapling/run_crawl4ai(_search).py
├── engines/                          # 采集引擎源码（scrapling / crawl4ai）
├── dbx-runtime/                      # ★ DBX 本地运行时：dbx-web.exe + dist + data/dbx.db（连接配置）
├── .venv/                            # Python 虚拟环境（uv 管理，含 pymysql/psycopg 驱动）
├── pyproject.toml / uv.lock / .python-version   # Python 环境与依赖锁定
├── 启动.cmd / 启动.sh                 # 一键启动（自动拉起 dsh + DBX）
└── docs/                             # 说明文档
```

> 采集产物一律落在**当前会话工作区**（打开 BoBo 时选定的目录）下的 `data/`，不写入 BoBo 根目录。

## 3. Agent 预设机制（一切模式的底座）

每个模式对应 `dsh/apps/cli/config/agent-presets/<name>/` 下的两个文件：

- **`preset.yml`**：预设元数据，`name`（界面显示名）、`description`、`order`（排序）。
- **`agent.cordis.yml`**：Agent 实际装配——一个 `persona`（`@deepseek-ai/dsh-persona`，把模式规则写进 system prompt）+ 一组工具行。

dsh 启动时扫描该目录按 `order` 注册；预设切换在 **Web 端设置 → Agent 预设** 完成，新增/修改预设需**重启**（`cd dsh && pnpm bobo`）生效。

模式差异的本质 = **persona 提示词不同 + 挂载的工具集不同**：
- 采集模式工具集极简（采集工具 + shell + fs + ask-user，无 skills/plan/subagent）。
- 工作流模式挂载"逆向模式的近标准工具集 + 采集工具"（shell、fs、skill、plan、subagent、workflow、web 等）。

## 4. 采集模式（crawl）工作流程

**定位**：用户给出网址，智能体自动检测并调用本地引擎抓取网页、把内容保存为 Markdown 到工作区，并汇报结果。核心配置文件：`dsh/apps/cli/config/agent-presets/crawl/`。

### 4.1 一句话流程

```
用户输入 URL → 智能体检测 URL（persona 规则）→ 调用 crawl_fetch → 编排层选引擎并调用 Python 脚本
→ 引擎抓取 + 转 Markdown → 落盘工作区 data/ → 回传 JSON → 智能体汇报（路径/状态码/摘要）
```

### 4.2 逐步拆解

**① 意图识别（persona 提示词驱动）**
- 输入中出现 `http://` / `https://` 链接即触发采集，无需用户说"请采集"。
- 多个 URL → 逐个采集后**汇总**报告。
- 用户明确说"不采集"或仅讨论网站 → 不触发。

**② 引擎选择**
- 默认 `camoufox`（抗检测真实浏览器，可渲染 JS、处理弹窗/反爬）。
- 用户可指定 `scrapling`（轻量 HTTP，静态页快）或 `crawl4ai`（LLM 友好的 Markdown 提取）。

**③ 工具调用（Node 编排层）**

`tool-acquisition` 插件注册 `crawl_fetch` 工具，收到 `{url, engine, selector?, outFile?}` 后，拼出脚本参数并调用 `.venv` 中的 Python：

```
python scripts/run_camoufox.py --url <url> --out <工作区>/data/<文件名> --auto-name
```

| 配置键 | 作用 |
| --- | --- |
| `pythonBin` / `scriptsDir` / `dataDir` | 默认留空，插件按自身位置自动定位 BoBo 根的 `.venv` / `scripts` / `data`（跨机器可移植） |
| `timeoutMs` | 执行超时（120000ms） |

**④ Python 引擎抓取（执行层）**
- camoufox：headless 启动真实浏览器 → 导航 → 关 Cookie 弹窗 → 等待 JS 渲染 + 滚动触发懒加载 → 取渲染后 HTML/正文 → 转 Markdown。
- 结果以**单行 JSON** 输出到 stdout：`{savedTo, status, preview, title}`。

**⑤ 落盘与汇报**
- Markdown 按 `站点域名_页面标题_时间戳.md` 命名，落**当前工作区** `data/`（缺目录自动创建）。
- 编排层解析 JSON 后回给智能体 → 智能体向用户汇报：**保存路径 + HTTP 状态码 + 内容摘要（约 200 字）**，其余信息不输出。

### 4.3 采集模式典型交付

```
采集完成：
- URL: https://news.qq.com/...
- HTTP 状态码: 200
- 引擎: camoufox
- 保存路径: <工作区>/data/news_qq_com_标题_20260820-154238.md
- 内容摘要: 这是一篇关于……（前 200 字）
```

**相关文件**：`agent-presets/crawl/preset.yml`、`agent-presets/crawl/agent.cordis.yml`、`packages/acquisition/tool-acquisition/src/index.ts`、`scripts/run_camoufox.py` 等。

## 5. 工作流模式（workflow）工作流程

**定位**：在采集基础之上更进一步——把网页数据按用户要求清洗后写入其指定的数据库表，并把"提取 → 入库"逻辑沉淀为**可复用 Python 脚本**。核心配置文件：`dsh/apps/cli/config/agent-presets/workflow/`，配套技能：`~/.dsh/skills/db-extraction/`。

### 5.1 触发条件

输入含**采集/入库关键词**（采集、爬取、抓取、入库、存表、写入数据库、存数据）且**带网址或数据库目标**时才触发；仅讨论网站/数据库则不触发。无网址但明确要入库 → 走数据库侧流程（跳过采集阶段）。

### 5.2 六阶段 SOP 全流程

**阶段一：读取数据库字段（只针对被授权的目标表）**

1. 定位 BoBo 根目录（含 `dbx-runtime` 的目录），随后所有 `dbx_connector` 命令均带 `--bo-bo-root <根目录>`（否则工作区里找不到 `dbx.db`）。
2. 加载 `db-extraction` 技能，运行 `dbx_connector list-connections` 读取 DBX 面板已保存连接（数据源 `dbx-runtime/data/dbx.db`）。目标库已存连接 → 直接复用；没有 → 询问用户或引导其在左侧"数据库"面板新建。
3. **直接 `describe-table <目标表>`** 校验存在并读取全部字段（字段名/类型/主键/可空）。**不使用 `list-tables` 枚举其它表**。
4. 授权边界（强制）：只操作用户明确给出的目标表；参考表仅 `describe-table` 只读，绝不写入。
5. 空白/新表 → 询问 CREATE TABLE SQL 或逐个定义字段，只建目标表。

**阶段二：确认字段含义（严格逐一）**

- 拿到目标表全部字段后，**逐个字段**用 `ask_user` 逐一询问含义与数据来源，**问完一个再问下一个**，不跳过、不默认通过。
- 每个字段可给**推荐方案**（依据网页信息或建议默认值，如 NOT NULL 配置类字段 `fetcher`/`enabled`/`sort_order`/`created_at`/`updated_at` 等），但**推荐不能代替询问**。
- 此步先只确认含义；能否提取、填 NULL 还是固定值留到阶段四。

**阶段三：抓样品页了解页面结构**

- 优先查看工作区 `crawl_script/` 是否已有匹配该网址类型的逆向脚本，有则先跑它拿样品；否则用 `crawl_fetch` 抓一个样品页，保存到 `{{cwd}}/data/`。
- 阅读样品，**枚举网页能提供的信息点**（标题/正文/列表项/价格/日期/来源链接等）与样例值；同类型网址只需侦察一个样品。

**阶段四：核对字段满足度 & 补空值/固定值**

- 把阶段二确认的每个字段逐一对照样品页：能提取的 → 标记数据来源。
- 页面**满足不了**的字段，**逐个**询问用户：填 NULL 空值，还是填用户提供的固定值。
- 整理最终字段映射给用户**再确认一次**，确认后才进入写脚本阶段。

**阶段五：写提取入库脚本（复用模板省 token）**

- 先读工作区 `extraction_scripts/index.md`：若已有"同类型网址 → 同目标表"脚本，直接复用，不重新生成。
- 否则加载 `db-extraction` 技能，把 `extraction_template.py` 复制为 `{{cwd}}/extraction_scripts/<名称>.py`，**只填 `# ⛏️ GEN-CUSTOM` 定制区**：
  - 连接名、目标表、`dbx_data_dir`（`<根目录>/dbx-runtime/data`）、去重键、固定值、`extract_rows()`（把采集结果拆成记录）。
- 通用骨架（读数据、取字段、连库、UPSERT、预览、CLI）来自模板，不重写。生成时会把 `dbx_connector.py` 一并复制到 `extraction_scripts/`，使其独立于技能目录运行。

**阶段六：批量采集与入库（采集/入库分离，UPSERT 去重）**

1. **批量来源**：一批 URL / 一个 URL 清单文件（每行一个）/ 已抓好的 `data/` 目录。
2. **采集落 `data/`**：对清单每个网址，优先运行匹配的逆向脚本，否则 `crawl_fetch` **按引擎降级**（camoufox → 失败转 scrapling → 再失败转 crawl4ai）。
3. **入库调脚本**：`python <脚本> --data {{cwd}}/data`（遍历文件提取并写入目标表）。
4. **预览再写库**：先 `--dry-run` 展示待写入行 → 用户确认 → 正式运行 → **只写目标表**，按主键/唯一键 **UPSERT**（存在更新、不存在插入，实现无重复入库）。无唯一键且未指定去重键时退化为追加插入并在汇报说明。
5. **汇报**：插入/更新条数、目标表、脚本路径。

### 5.3 端到端示例

用户输入：*"把 https://example.com/books 的书单采集下来，存到 MySQL_tloz 的 book 表"*

1. 识别采集词 + 网址 → `list-connections` 确认复用连接 `MySQL_tloz` → `describe-table book`（跳过 `list-tables`）读取字段。
2. 逐一 ask_user 确认 `book` 表每个字段含义（带推荐方案，但逐个征求）。
3. 抓一个样品页，枚举书名/作者/价格/简介等信息点；检查 `crawl_script/` 有无匹配脚本。
4. 逐字段核对能否提取；页面满足不了的逐个询问填 NULL 还是固定值；整理映射再确认一次。
5. 读 `index.md` 无现成脚本 → 复制 `extraction_template.py` 生成 `extract_book.py`（只填 GEN-CUSTOM，`dbx_data_dir` 填根目录 dbx-runtime/data），登记 index.md。
6. 批量采集落 `data/` → `extract_book.py --data data --dry-run` 预览 → 确认 → 正式 UPSERT → 只写 `book` 表 → 汇报条数。

### 5.4 关键支撑组件

| 组件 | 位置 | 作用 |
| --- | --- | --- |
| 技能 SOP | `~/.dsh/skills/db-extraction/SKILL.md` | "采集 → 确认字段 → 提取 → UPSERT 入库"流程说明 |
| 连接库 | `~/.dsh/skills/db-extraction/dbx_connector.py` | 读 DBX 已存连接并连库（list/describe/upsert；按 db_type 选 pymysql/psycopg/sqlite3） |
| 脚本模板 | `~/.dsh/skills/db-extraction/extraction_template.py` | 提取入库骨架，GEN-CUSTOM 定制区 |
| 数据库驱动 | `pyproject.toml`（pymysql、psycopg） | 经 `uv sync` 装入 `.venv` |

> 技能发现即时、无需重启；但"工作流模式行为提示词"存于预设 `agent.cordis.yml`，改动需**重启生效**。

## 6. 与其余能力的联动

- **DBX 数据库面板**（左侧导航"数据库"，内嵌 `http://localhost:4224`）：用户在此维护数据库连接，连接配置落 `dbx-runtime/data/dbx.db`；工作流模式正是**复用这些已保存连接**。独立服务由启动脚本拉起。
- **逆向模式**（order 6）：生成爬虫脚本存档工作区 `crawl_script/`、数据落 `data/`；工作流模式的样品侦察与批量采集阶段会**优先复用这些逆向脚本**。脚本模板：`~/.dsh/skills/reverse-crawler/crawl_template.py`。
- **MCP 工具**：js-reverse 等网页逆向 MCP 挂载于 `~/.dsh/cordis.patch.yml`，服务于逆向分析。
- **技能库**：`settings.yaml` 的 `skill-library` 为唯一数据源，`skill-filesystem` 扫描 `~/.dsh/skills/` 与项目 `.agents/skills/`；**模式需显式挂 `skill-filesystem` + `tool-skill` 才能调用技能**（采集模式不含，工作流/逆向模式含）。

## 7. 合规与安全要点

- 采集尊重目标网站服务条款与反爬规则；不用于绕过付费墙或损害他人权益。
- 数据库写入**仅限用户授权库表**，用户给的参考表只读、绝不写入；写库前必须 dry-run 预览并获得确认。
- 字段确认严格逐一、推荐方案不代替询问；行为偏离（如枚举未授权表、一次性批量确认）属需纠正的运行偏差。
- 采集/写入动作前向用户说明将运行的命令，不静默结束回合。
