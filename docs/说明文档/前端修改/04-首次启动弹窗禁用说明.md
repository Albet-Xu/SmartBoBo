# 首次启动弹窗禁用说明文档

## 1. 修改背景

当项目部署到其他电脑时，首次打开网页端会弹出两个弹窗：
1. **内测声明弹窗**：显示 DeepSeek Harness 的内测声明信息
2. **DeepSeek API 填写弹窗**：要求用户填写 DeepSeek API Key

这两个弹窗对于已经配置好环境的用户来说是不必要的，会影响用户体验。

## 2. 修改目标

禁用首次启动时的两个弹窗，让用户直接进入主界面。

## 4. 弹窗功能说明

### 4.1 内测声明弹窗（WelcomeNotice）

**功能**：显示 DeepSeek Harness 的内测声明信息，告知用户当前版本仍在测试阶段。

**触发条件**：用户首次打开网页端，且未确认过内测声明。

**确认状态**：通过 Host settings 持久化存储，用户确认后不再显示。

### 4.2 DeepSeek API 填写弹窗（DeepSeekOnboardingDialog）

**功能**：引导用户配置 DeepSeek 官方 API Key。

**触发条件**：用户首次打开网页端，且未配置任何可用的 LLM 提供商。

**配置状态**：检查是否存在可用的 DeepSeek API Key，配置后不再显示。

## 5. 影响分析

### 5.1 正面影响

1. **提升用户体验**：用户无需手动关闭弹窗即可直接使用
2. **简化部署流程**：部署到新环境时无需手动确认弹窗
3. **减少配置步骤**：用户可以在设置中手动配置 API，无需在启动时强制配置

### 5.2 潜在影响

1. **用户可能不知道 API 配置方式**：用户需要在设置中手动配置 DeepSeek API
2. **内测声明信息无法传达**：用户可能不知道当前版本的测试状态

### 5.3 解决方案

1. 在 `README.md` 或部署文档中说明 API 配置方式
2. 在设置页面的"模型"部分提供 API 配置入口
3. 用户可随时在设置中配置和修改 API Key

## 7. 恢复弹窗

如果需要恢复这些弹窗，只需将注释的代码取消注释即可：

```typescript
ctx.slots.inject('settings.onboarding', () => ctx.slots.register({
  name: 'settings.onboarding',
  id: 'welcome-notice',
  order: -100,
  inject: welcomeInjected,
}, WelcomeNotice))
ctx.slots.inject('settings.onboarding', () => ctx.slots.register({
  name: 'settings.onboarding',
  id: 'deepseek-official',
  order: 0,
  inject: deepSeekOnboardingInjected,
}, DeepSeekOnboardingDialog))
```

## 9. 后续优化建议

### 9.1 配置化管理

可以将弹窗的启用/禁用状态做成配置项，方便不同部署场景的需求：

```typescript
// 在配置文件中添加
onboarding: {
  enableWelcomeNotice: false,
  enableDeepSeekOnboarding: false,
}
```

### 9.2 条件启用

可以根据环境变量或配置决定是否显示弹窗：

```typescript
const enableOnboarding = process.env.DSH_ENABLE_ONBOARDING === 'true'
if (enableOnboarding) {
  // 注册弹窗
}
```

### 9.3 自定义弹窗内容

如果需要保留弹窗但修改内容，可以修改 `onboarding-copy.ts` 文件中的文案。
