# 启动失败问题修复说明

> **修复日期：** 2026-08-23  
> **问题类型：** 配置错误导致启动失败  
> **修复状态：** ✅ 已完成

---

## 问题现象

启动时报错：

```
Error: dsh: plugin tree failed to load: failed to apply loader entry llm-pi-ai 
(@deepseek-ai/dsh-llm-pi-ai): llm-pi-ai: provider "moonshot" resolves no models; 
the installed catalog does not describe this route, so its models must be listed 
in configuration
```

---

## 问题原因

**根本原因：** `llm-pi-ai` 适配器要求，对于 **pi-ai catalog 中不存在的提供方**，必须在配置中**显式声明模型列表**。

**受影响的提供方：**
- `moonshot` - 未声明模型
- `opencode-go` - 未声明模型

**错误机制：**
```
pi-ai catalog 不包含 moonshot/opencode-go
    ↓
配置中只声明了 apiKeyEnv
    ↓
没有模型列表
    ↓
解析失败：resolves no models
    ↓
启动失败
```

---

## 修复方案

### 修复位置

**文件：** `dsh/packages/bundle/base/cordis.patch.yml`

### 修复内容

为 `moonshot` 和 `opencode-go` 添加模型列表配置：

```yaml
# Moonshot（Kimi）- 需要配置模型列表
moonshot:
  apiKeyEnv: MOONSHOT_API_KEY
  models:
    - id: moonshot-v1-8k
      name: Moonshot v1 8K
      contextWindow: 8000
    - id: moonshot-v1-32k
      name: Moonshot v1 32K
      contextWindow: 32000
    - id: moonshot-v1-128k
      name: Moonshot v1 128K
      contextWindow: 128000

# OpenCode Go（用户通过 Web 界面配置）- 需要配置模型列表
opencode-go:
  apiKeyEnv: OPENCODE_GO_API_KEY
  models:
    - id: opencode-go-default
      name: OpenCode Go Default
      contextWindow: 128000
```

## 技术说明

### pi-ai 提供方分类

pi-ai 适配器将提供方分为两类：

#### 1. Catalog 提供方（已内置）

这些提供方在 pi-ai 的 catalog 中已有定义，**不需要**配置模型列表：

- ✅ `deepseek` - DeepSeek 官方
- ✅ `openai` - OpenAI 官方
- ✅ `anthropic` - Anthropic 官方
- ✅ `google` - Google AI 官方

**配置方式（无需模型列表）：**
```yaml
deepseek:
  apiKeyEnv: DEEPSEEK_API_KEY
```

#### 2. 自定义提供方（需配置模型）

这些提供方**不在** pi-ai catalog 中，**必须**配置模型列表：

- ❌ `moonshot` - Moonshot（Kimi）
- ❌ `opencode-go` - OpenCode Go
- ❌ 其他第三方网关

**配置方式（必须带模型列表）：**
```yaml
moonshot:
  apiKeyEnv: MOONSHOT_API_KEY
  models:
    - id: moonshot-v1-8k
      name: Moonshot v1 8K
      contextWindow: 8000
```

### 模型配置字段

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | ✅ | 模型唯一标识符 |
| `name` | ❌ | 显示名称（可选，默认同 id） |
| `contextWindow` | ❌ | 上下文窗口大小（可选） |
| `maxTokens` | ❌ | 最大输出 token 数（可选） |
| `reasoningEfforts` | ❌ | 推理档位（可选） |

## 其他可能的问题

### 如果仍然启动失败

#### 检查清单

- [ ] 配置文件语法正确（YAML 缩进）
- [ ] 模型 ID 非空
- [ ] 至少配置一个模型
- [ ] contextWindow 为正整数

#### 常见错误

**错误 1：缩进不正确**
```yaml
# ❌ 错误
moonshot:
apiKeyEnv: MOONSHOT_API_KEY
models:
  - id: moonshot-v1-8k

# ✅ 正确
moonshot:
  apiKeyEnv: MOONSHOT_API_KEY
  models:
    - id: moonshot-v1-8k
```

**错误 2：模型列表为空**
```yaml
# ❌ 错误
moonshot:
  apiKeyEnv: MOONSHOT_API_KEY
  models: []

# ✅ 正确
moonshot:
  apiKeyEnv: MOONSHOT_API_KEY
  models:
    - id: moonshot-v1-8k
```

**错误 3：缺少必填字段**
```yaml
# ❌ 错误
moonshot:
  apiKeyEnv: MOONSHOT_API_KEY
  models:
    - name: Moonshot v1 8K  # 缺少 id

# ✅ 正确
moonshot:
  apiKeyEnv: MOONSHOT_API_KEY
  models:
    - id: moonshot-v1-8k
      name: Moonshot v1 8K
```

## 添加新提供方的步骤

如果需要添加其他提供方（如 Azure OpenAI、本地模型等）：

### 步骤 1：确定提供方类型

**查询 pi-ai catalog：**
```bash
grep -r "supportedProviders" dsh/packages/llm/llm-pi-ai/
```

如果提供方在 catalog 中 → 只需配置 `apiKeyEnv`  
如果不在 catalog 中 → 需要配置 `apiKeyEnv + models`

### 步骤 2：添加配置

在 `bundle/base/cordis.patch.yml` 中添加：

```yaml
your-provider:
  apiKeyEnv: YOUR_PROVIDER_API_KEY
  models:
    - id: your-model-1
      name: Your Model 1
      contextWindow: 100000
```

### 步骤 3：重启验证

```cmd
cd E:\SmartBoBo
启动.cmd
```

## 总结

### 问题根源

- pi-ai 适配器对非 catalog 提供方要求显式声明模型列表
- 配置中只声明了 `apiKeyEnv`，没有 `models`

### 修复方法

- 为 `moonshot` 添加 3 个模型配置
- 为 `opencode-go` 添加 1 个模型配置

### 经验教训

**添加新提供方时的检查清单：**

1. ✅ 确认提供方是否在 pi-ai catalog 中
2. ✅ 如果不在，必须配置模型列表
3. ✅ 模型列表至少包含一个模型
4. ✅ 每个模型必须有 `id` 字段
5. ✅ 重启服务验证配置
