## 问题诊断

### 第一次修复（未完全生效）

**修改的文件：** `dsh/python/sdk-runtime/src/deepseek_harness_runtime/runtime/cordis.yml`

**问题：** 这个文件**不是** Web 启动时加载的配置文件！

### 根本原因

dsh web 启动流程：

```
pnpm bobo
  ↓
加载 bundle 配置
  ↓
dsh/packages/bundle/base/cordis.patch.yml  ← 真正的配置位置
  ↓
应用 patch 叠加
  ↓
dsh/packages/bobo/cordis.patch.yml（端口配置）
dsh/patch/web-acquisition.yml（采集工具）
```

**`runtime/cordis.yml` 的用途：**
- 仅用于 SDK 运行时（Python SDK）
- 不影响 Web 界面
- 是"备用"配置，不是主配置

## 正确的修复位置

**文件：** `dsh/packages/bundle/base/cordis.patch.yml`

**原因：**
1. 这是 dsh web 启动时的**基础 bundle 配置**
2. 所有 Web 模式都基于这个配置
3. 修改后立即生效（重启服务）

## 修复内容

### 修改 1：替换适配器（第 450 行）

**原配置：**
```yaml
- id: llm-deepseek
  name: '@deepseek-ai/dsh-llm-deepseek'
```

**新配置：**
```yaml
# ★ 多模型适配器（llm-pi-ai）
- id: llm-pi-ai
  name: '@deepseek-ai/dsh-llm-pi-ai'
  config:
    providers:
      deepseek:
        apiKeyEnv: DEEPSEEK_API_KEY
      openai:
        apiKeyEnv: OPENAI_API_KEY
      anthropic:
        apiKeyEnv: ANTHROPIC_API_KEY
      google:
        apiKeyEnv: GOOGLE_API_KEY
      moonshot:
        apiKeyEnv: MOONSHOT_API_KEY
```

### 修改 2：更新默认模型选择器（第 66 行）

**原配置：**
```yaml
- id: agent-default-model
  config:
    provider: deepseek-official  # 旧适配器路由
```

**新配置：**
```yaml
- id: agent-default-model
  config:
    provider: deepseek  # 新适配器路由（pi-ai 的 deepseek）
```

## 重要教训

### dsh 配置层次

```
1. Bundle 配置（基础）
   └─ dsh/packages/bundle/base/cordis.patch.yml ← 修改这里
   
2. Profile 配置（用户自定义）
   └─ $DSH_HOME/cordis.patch.yml
   
3. Patch 叠加（启动参数）
   └─ --patch packages/bobo/cordis.patch.yml
   └─ --patch patch/web-acquisition.yml
```

### 修改优先级

```
Patch 叠加 > Profile 配置 > Bundle 配置
```

### 最佳实践

1. **修改基础配置** → 编辑 `bundle/base/cordis.patch.yml`
2. **用户自定义** → 编辑 `$DSH_HOME/cordis.patch.yml`
3. **临时测试** → 使用 `--patch` 参数
