# 26-代理命令防呆优化操作指南

> 本指南记录 BoBo 中 `/proxy` 命令的防呆化改造：新增 `on`/`off` 语义、支持"一行开启并采集"、
> 以及"开启/关闭都要大模型向用户确认"。附改动文件清单、实现细节与验证方法。

---

## 一、问题背景

改造前 `/proxy` 命令存在三个防呆性缺陷：

1. **吞参数**：输入 `/proxy https://zhuanlan.zhihu.com/p/...` 时，URL 被当成命令参数吃掉，
   根本不会被送去采集（persona 的"检测到 URL 就自动采集"只对普通消息生效）。
2. **往返切换误触发**：`/proxy` 无参会按"当前状态取反"来切换，导致重复敲一次反而把代理**关掉**。
3. **静默无模型回复**：斜杠命令在宿主侧执行，只记录日志事件、**不开一轮对话**，模型不会被唤起，
   所以开启/关闭后没有任何 AI 文案反馈，用户觉得"没反应"。

---

## 二、改造目标

1. 明确 `on`/`off` 两个语义值：`/proxy on` 开、`/proxy off` 关。
2. 无参 `/proxy` **固定开启**（幂等），不再往返切换。
3. 支持**一行开启并采集**：`/proxy on` 换行再接采集指令与网址 → 先开代理，再把后续内容交给模型走代理采集。
4. 开启和关闭都由**大模型向用户开口确认**（同时保留命令卡片的简短确认作为兜底，即"双通道"）。

## 四、实现细节

### 1. 参数解析（防呆核心）

对 `/proxy` 后的内容做规则化解析：

```ts
const m = /^\s*(on|off)\b([\s\S]*)$/i.exec(trimmed)
if (m !== null) { mode = 首词=== 'on'; rest = 剩余内容 }
else            { mode = true;  rest = 整段 }   // 无参或非 on/off → 默认开启
```

- 只认最前面的 `on`/`off` 单词，其余一律当"要采集/处理的内容"（`rest`）转给模型，不再吞掉。
- `/proxy offline` 这类以 on/off 开头的普通词因 `\b` 词边界不命中，会按"开启 + 内容"处理，不会被误判为关。

### 2. 开关落库

`mode !== current` 时才写入会话日志：

```ts
agent.session.append('proxy/enabled', { enabled: mode })
```

幂等：重复 `/proxy on`（已开）不再重复 append，但仍会给用户确认。

### 3. 唤醒模型（双通道）

使用 Agent 的 `followup(createUserMessage(...))` 开启一轮对话：

- **有 rest**：把 rest 作为一条 user 消息发给模型 → 模型按 persona 检测 URL 调 `crawl_fetch`，
  因代理已先落库，采集走代理并正常回复用户；
- **无 rest（裸 on/off）**：注入一句确认提示（如"用户开启了代理模式，请向用户做一句简短确认"）
  → 模型向用户开口，例如"代理模式已开启/关闭"。

同时 `handler` 返回 `CommandResult`，命令卡片显示简短状态（如"代理模式已开启……"）作为模型不可达时的兜底。

## 五、使用说明

| 输入 | 行为 |
|---|---|
| `/proxy on` | 开启代理模式，模型确认"已开启"（已开再敲仍确认，幂等） |
| `/proxy off` | 关闭代理模式，模型确认"已关闭"，后续采集走本地 |
| `/proxy`（无参） | 等同 `/proxy on`，固定开启 |
| `/proxy on` + 换行 + 采集串 | 先开代理，再把采集串交给模型走代理采集 |

**一行开启并采集中文示例**：

```
/proxy on
采集，https://zhuanlan.zhihu.com/p/2069755118958990484
```

模型确认开启后直接通过代理采集该网址并回复结果。

> 仅对采集/逆向/工作流三种模式生效（该命令只装配进这三个预设）。

## 六、验证方法

1. 类型检查：
   ```bash
   cd dsh
   pnpm exec tsc -p packages/proxy/command-proxy/tsconfig.json
   ```
2. 重建 host 包（生成 `lib/index.js`）：
   ```bash
   pnpm run build:lib:host
   ```
3. 重启 bobo（`cd dsh && pnpm bobo`），在新会话中分别验证：
   - `/proxy on` / `/proxy off` → 模型开口确认；
   - `/proxy`（无参）→ 开启，不误关；
   - `/proxy on` 换行 `采集，<url>` → 开启并走代理采集。

---

## 七、注意事项

1. 命令卡片 + 模型确认是"双通道"：即使模型暂不可达，用户也能从卡片看到代理状态。
2. 无参 `/proxy` 恒为开启（幂等）；如需关闭必须显式 `/proxy off`。
3. 改动为未提交工作区；部署/换机需重新 `pnpm install`（新增了 dsh-llm 依赖）并重启才生效。
