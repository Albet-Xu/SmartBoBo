# 27-技能按需加载（triggers 触发词）操作指南

> 本指南记录 SmartBoBo「技能按需加载」功能的实现原理、改动文件清单、使用配置方法与验证方式，供后续维护与排查。

---

## 一、功能背景

技能系统的加载链路本来的设计诉求是：**技能正文按需加载**——`ctx.skills.list()` / `snapshot()` 只返回摘要（`name` + `description`），`tool-skill` 在每次 `agent/pre-step` 用 `<system-reminder>` 目录列出所有模型可调用技能，模型再调 `skill {name}` 工具取正文。

但目录把每个已安装技能都列出来，**无关问题同样占 token、转移注意力**。以 `install-mcp-and-skills` 为例，本应只在用户要求"安装 MCP / 技能"时出现，实际却常驻目录。本次改动新增**触发词门槛**：技能可声明 `triggers`，仅当当前问题命中触发词时才进入目录、才可被 `skill` 工具加载；未命中则完全不露出。

此机制对**所有技能通用**，**默认关闭**（不声明 `triggers` 的技能维持原常驻行为）。

---

## 二、核心功能点

1. **通用 frontmatter `triggers`**：任意技能在 `SKILL.md` 声明 `triggers: [<短语>, ...]` 即开启按需露出。
2. **命中规则**：对用户文本做 `小写 + 空白折叠`，任一触发词作为**子串**出现即命中（触发词同样折叠）。大小写、多余空格不影响匹配。
3. **缺省 / 空 / 非列表**：视为无门槛，技能常驻目录（与改动前行为一致）。
4. **目录门槛**：每次 `agent/pre-step` 用本步真实用户文本过滤，未命中 → 该技能本轮不在目录中，`skill` 工具也查不到。
5. **加载器门槛（防御内层）**：`skill` 工具执行时用会话表面最新直接用户消息再校验一次，未命中返回"is gated and does not match the current request"。
6. **`/name` 用户手势不设门槛**：用户显式以 `/技能名` 调用天然绕过目录，符合语义。

---

## 三、实现原理（数据流）

```
用户输入"帮我安装 MCP 服务器"
  └── agent/pre-step
        ├── activeUserText(messages)  提取本步直接用户文本（仅 source.kind==='user'）
        ├── triggerMatches(text, skill.triggers)  任一触发词为子串即命中
        └── 目录过滤：modelInvocable && triggerMatches
              ├── 命中   → install-mcp-and-skills 进入 <available_skills>
              │            └── 模型调 skill 工具 → 再校验一次 → 加载正文
              └── 未命中 → install-mcp-and-skills 不出现在目录，不可加载
```

目录按"当前问题"动态变化：命中/未命中切换时，digest 变化 → 走既有 update 机制重发替换目录；同一主题内目录保持稳定。

## 五、使用方法（如何给技能开启按需加载）

编辑技能目录下的 `SKILL.md`，在 frontmatter 增加 `triggers` 列表：

```yaml
---
name: install-mcp-and-skills
description: 从 GitHub 找到并安装 MCP 服务器或技能包到本地……
triggers:
  - 安装 mcp
  - 安装技能
  - 安装
  - mcp
  - 技能
  - install
  - skill
disable-model-invocation: false
user-invocable: false
---
```

要点：

- 只给"低频辅助型"技能加，避免给常驻核心技能加。
- 触发词既符合中文也符合英文，能覆盖常见措辞即可。
- **不要放过于通用的词**（如裸 `skill`、`技能`），否则用户一提到该词就会把它露出，削弱按需效果；用更精确的短语（如 `安装 mcp`）更好。
- 错误类型（如 `triggers: mcp` 非列表）会被省略并视为无门槛，不会报错、不会剔除该技能。

---

## 六、生效方式

- 技能发现为实时：修改 `SKILL.md` frontmatter 后**无需重启服务**，下次目录观察即生效。
- 仅改动 `dsh/packages/skill/*` 源码时需重启服务（`cd dsh && 启动`）；若只改技能自身 frontmatter 则不用。

---

## 七、验证方法

1. **本质生效（未命中不露出）**：正常会话中发送无关问题（如"请采集这个网页"），观察目录 `<available_skills>` 不含 `install-mcp-and-skills`。
2. **命中才露出**：发送"帮我安装 MCP 服务器"，目录应包含 `install-mcp-and-skills`，模型可调 `skill` 工具加载正文。
3. **加载器内层门槛**：未命中主题时，即便模型误调 `skill {name: install-mcp-and-skills}`，应返回"is gated and does not match the current request"错误。
4. **`/name` 手势**：用户直接输入 `/install-mcp-and-skills`，仍可正常注入且不设门槛。
5. **无门槛技能不受影响**：未声明 `triggers` 的技能（其他常驻技能）行为与改动前一致。

## 九、以后自己改要点

- **加按需技能**：在对应 `SKILL.md` frontmatter 增加精确的 `triggers` 列表。
- **调触发词**：直接改 `triggers` 列表，技能发现实时，无需重启。
- **改源码**：涉及 `dsh/packages/skill/{skill,skill-filesystem,tool-skill}` 时，同步更新三处测试与对应的双语 README。
- **匹配规则**：大小写与空白不敏感的子串匹配；如需改规则（如整词匹配），位于 `tool-skill/src/index.ts` 的 `triggerMatches`。
