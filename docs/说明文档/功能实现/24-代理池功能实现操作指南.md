# 24-代理池功能实现操作指南

> 本指南记录 SmartBoBo 代理池功能的实现流程、修改文件清单、配置说明与使用方法。

---

## 一、功能概述

代理池功能允许用户配置多个代理 API 源，通过 `/proxy` 命令开启代理模式，使采集/逆向/工作流模式的网页访问通过代理进行，以避免反爬限制。

### 核心功能点

1. **`/proxy` 斜杠命令**：在采集模式、逆向模式、工作流模式中可用，用于开启/关闭代理模式（会话级）。
2. **代理池配置**：全局一份，存放在设置 → 代理池，支持多个代理 API 源的增删改。
3. **两种取用策略**：用户可在设置中选择"缓存轮询"或"实时拉取"。
4. **自动重试与询问**：代理失效时自动重试 3 次，全失败后询问用户是否走本地网络。

### 代理池数据流

```
用户输入 /proxy 命令
  └── 会话事件 proxy/enabled 记录开关状态
        └── crawl_fetch 工具读取状态
              ├── 开启 → 从代理池取可用代理 → 传递 --proxy 给 Python 脚本
              │         ├── 成功 → 通过代理采集
              │         └── 失败 → 重试(默认3次) → 全失败返回"代理失效"
              │                       └── 模型用 ask_user 询问用户
              └── 关闭 → 直接本地网络采集
```

### 构建验证

构建已验证通过：

```bash
cd dsh
pnpm run build
```

构建成功后，前端页面会在"设置"菜单的"技能库"下方显示"代理池"选项。

## 四、配置说明

### 代理池 Settings Namespace

**命名空间**：`proxy-pool`（存放在 `~/.dsh/settings.yaml`）

**Schema**：

```typescript
interface ProxyPoolSettings {
  sources: ProxySource[]       // 代理源列表
  fetchStrategy: 'cache' | 'realtime'  // 取用策略
  enabled: boolean             // 总开关
  maxRetries: number           // 最大重试次数（默认 3）
  timeoutMs: number            // 超时时间（毫秒，默认 30000）
}

interface ProxySource {
  name: string                 // 备注名
  apiUrl: string               // 代理 API 地址
  apiKey: string               // API Key
  pwd: string                  // 密码
  getnum: number               // 每次获取数量（默认 50）
  httptype: string             // 代理类型（http/socks5）
  geshi: string                // 格式参数（默认 '2'）
  fenge: string                // 分隔参数（默认 '1'）
  enabled: boolean             // 是否启用此源
}
```

> 界面说明：新增源面板只展示并填写 `name` 与 `apiUrl` 两个字段；`apiKey`/`pwd`/`getnum` 及 `httptype`/`geshi`/`fenge`
> 在保存时保留默认值（空串 / 50 / http / '2' / '1'）。若把凭证参数拼进 `apiUrl` 的查询串，后端按原样请求该地址；
> 若 `apiUrl` 不带查询串，后端仍会以 `${apiKey}`、`${pwd}` 等字段拼接参数（向后兼容）。

### 取用策略

1. **缓存轮询（cache）**：启动时/用完时取一批代理（如 50 个），轮询/随机换着用，用完再取新一批。省 API 调用，适合大规模采集。
2. **实时拉取（realtime）**：每次请求前调 API 拉一批，当场挑一个用。代理新鲜度高，但 API 调用量大。

### 校验方式

**请求目标网页本身**：一次请求同时完成"试代理通不通 + 真正采集"，不额外 ping 探测 URL。

## 五、使用方法

### 1. 配置代理源

1. 打开设置 → 代理池（设置界面最后一项，图标为链环）。
2. 点击"新增代理源"，填写：
   - 名称（如"大麦代理"）
   - API 地址：粘贴完整的代理 API 地址（`apikey`/`pwd`/`getnum` 等参数可一并含在 URL 内，支持查询参数内嵌，如
     `http://need1.dmdaili.com:7771/dmgetip.asp?apikey=...&pwd=...&getnum=50&httptype=1&geshi=1&fenge=1&operate=all`）
3. 选择取用策略（缓存轮询/实时拉取）。
4. 启用总开关。
5. 点击保存。

> 注：新增源界面仅保留"名称"和"API 地址"两个填写框。API Key、密码、每次获取数量不再单独填写，
> 请直接拼进 API 地址的查询参数中；当地址本身带查询参数时，后端按原样请求，不会再覆盖其中的凭证。

### 2. 开启代理模式

在采集模式、逆向模式或工作流模式中，输入：

```
/proxy on
```

模型会回复"代理模式已开启"，告知用户后续采集走代理池。

**支持三种写法（防呆）**：

| 输入 | 行为 |
|---|---|
| `/proxy on` | 开启代理模式，模型确认"已开启"（幂等：已开再敲仍确认开启） |
| `/proxy off` | 关闭代理模式，模型确认"已关闭"，后续采集走本地网络 |
| `/proxy`（无参） | 等同 `/proxy on`，固定开启，不再往返切换 |

**一行开启并采集**：在 `/proxy on` 后跟换行、再接采集指令与网址，会先开启代理、再把后续内容交给模型走代理采集，例如：

```
/proxy on
采集，https://zhuanlan.zhihu.com/p/2069755118958990484
```

命令卡片会给出简短确认，同时模型开口确认；若带采集内容，模型会直接通过代理采集该网址并回复结果。

### 3. 采集时使用代理

开启代理模式后，所有 `crawl_fetch` 调用会自动：
1. 从配置的代理池取一个可用代理。
2. 通过代理访问目标网页。
3. 如果失败，自动换下一个代理重试（最多 3 次）。
4. 全失败时，AI 会询问："代理失效，是否走本地网络进行访问网页？"

### 4. 逆向模式生成带代理的脚本

在逆向模式中，如果开启了代理模式，生成的爬虫脚本（`crawl_script/*.py`）会自动内嵌：
- 代理池取 IP 逻辑
- 轮换/随机策略
- 重试机制（默认 3 次）
- 全失效时 `input()` 询问用户

脚本可以脱离 BoBo 环境独立运行。

## 六、技术实现细节

### 1. `/proxy` 命令的会话级状态

- 命令触发 `session.append('proxy/enabled', { enabled })`。
- 事件溯源：最后一条 `proxy/enabled` 事件决定当前状态。
- 会话级：每次新建会话需重新敲 `/proxy`。

### 2. 代理池的按模式限定

- `/proxy` 命令插件**只装配进** `crawl`、`reverse`、`workflow` 三个模式的 `agent.cordis.yml`。
- **不加进** `packages/bundle/base/cordis.patch.yml`，确保 standard/code/cordis/minimal 四种基本模式无此命令。

### 3. 代理失效的两种询问载体

| 场景 | 载体 | 问题 |
|---|---|---|
| crawl_fetch 采集时 | AI 用 `ask_user` 工具 | "代理失效，是否走本地网络进行访问网页？" |
| 逆向脚本运行时 | 脚本 `input()` 函数 | "代理失效，是否走本地网络？" |

## 七、注意事项

1. **代理源凭证安全**：API Key 和密码存放在 `~/.dsh/settings.yaml`，不要提交 git。
2. **大麦代理限制**：动态代理 API 可能有频率限制，建议使用"缓存轮询"策略。
3. **Camoufox 代理支持**：已添加浏览器启动参数支持代理。
4. **Scrapling 代理支持**：Scrapling 的 StealthyFetcher 目前不直接支持代理参数，需通过其他方式配置（后续优化）。
