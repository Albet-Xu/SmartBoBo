# 31-目录化归类 + Camoufox 默认 + 增量更新（manifest）优化操作指南

> 本文档记录 SmartBoBo 三项优化：①采集产物（`data/`、`crawl_script/`、`extraction_scripts/`）按网站名建立子目录归类；
> ②逆向/工作流两模式生成的需要浏览器能力的爬虫代码，默认使用内置 camoufox 浏览器；
> ③增量更新：以每站点 `manifest.json` 为状态源，脚本侧 `--incremental` 只处理新增/变化，显著减少 token。
> 对应实现已完成，本文档用于排查定位与后续维护。

---

## 1. 优化 1：按网站名归类目录

### 1.1 约定

- **站点键 site key** = URL 域名去掉 `www.`（如 `news.qq.com`、`zhihu.com`），全项目统一；同一站点不同页面/子域名取同一站点键。
- 三个产物目录均按站点键分层：

```
<工作区>/
├── crawl_script/
│   ├── index.md                  # 站点键 → 脚本 登记表（追加不覆盖）
│   └── news.qq.com/
│       └── news_qq_article.py
├── data/
│   ├── news.qq.com/
│   │   ├── news_qq_<时间戳>.md
│   │   └── manifest.json         # 增量状态源（脚本维护）
│   └── _meta/                    # 非站点测试/调试产物归档
└── extraction_scripts/
    ├── index.md
    └── news.qq.com/
        ├── extract_article.py
        └── dbx_connector.py
```

### 1.2 落点

| 入口 | 行为 |
|---|---|
| 采集模式（crawl） | `crawl_fetch` 每次调用传 `saveDir=<工作区绝对路径>/data/<站点键>` |
| 逆向模式（reverse） | 脚本存 `crawl_script/<站点键>/`，`SITE_KEY` 填站点键；数据落 `data/<站点键>/`；在 `crawl_script/index.md` 追加登记 |
| 工作流模式（workflow） | 样品/批量采集落 `data/<站点键>/`；提取脚本存 `extraction_scripts/<站点键>/`（`CONFIG.site` 填站点键）；`extraction_scripts/index.md` 追加登记 |

- `data/proxy_failed.json` 是代理池**运行时台账**（`scripts/proxy_pool.py` 固定读写项目根 `data/`），**不要移动**；一次性的调试产物（如 `proxy_zhihu_test.md`）已归档到 `data/_meta/`。

## 2. 优化 2：需要浏览器的爬虫代码默认 camoufox

- `reverse-crawler` 模板 (`crawl_template.py`) 内置**双层获取**：`fetch_html()` 默认 `requests`（静态页零开销）→ `needs_render()` 判定需要渲染或 `--browser` 强制时，用**内置 camoufox**（`camoufox.sync_api.Camoufox`）渲染返回完整 HTML。
- persona/SKILL 红线：**需要浏览器能力的脚本一律 camoufox，禁止 selenium / 原生 playwright / 其它浏览器**；含渲染的脚本用 BoBo 的 `.venv/Scripts/python.exe` 运行（已装 camoufox，缺库会打印安装命令）。
- 采集端 `crawl_fetch` 本就统一 camoufox（见文档 28），此项主要补齐"模型手写脚本"侧的默认。

## 3. 优化 3：增量更新（manifest 驱动，最省 token）

### 3.1 设计

- **状态源**：`data/<站点键>/manifest.json`，采集脚本与提取脚本**共享**。条目字段：`url / title / crawled_at / content_hash(HTML指纹) / file_hash(落盘文件指纹) / file / extracted_at / extracted_hash`。
- **采集侧** `python crawl_script/<站点键>/<脚本名>.py --incremental`：
  - 每次落盘自动维护 manifest；增量时与 manifest 对比，**只抓新增或内容变化**的条目（`--force` 强制重抓、`--limit N` 限量）；
  - 列表型站点在定制区实现 `list_candidates()` 返回全部候选 `(url, 标题)`。
- **入库侧** `python extraction_scripts/<站点键>/<脚本名>.py --incremental [--dry-run]`：
  - 跳过 `extracted_hash == file_hash`（已入库且未变化）的文件，只处理新增/变化；
  - 正式入库成功回写 `extracted_hash`，下次自动跳过；UPSERT 仍按唯一键兜底去重；
  - 早期无 manifest 的历史数据首跑按"未入库"全量处理（UPSERT 安全），随后回写进入增量。
- **工作流模式新增「七、增量更新」分支**（触发词：增量/补采/续采/更新/最新数据），硬红线：**禁止重新读历史 data 文件、禁止 describe-table/整表 SELECT、禁止重新逐字段询问、不重新逆向**；模型只跑脚本并汇报 diff。

### 3.2 为什么省 token

增量时模型（或计划任务）只需执行两个 `--incremental` 命令并汇报 diff——**token ∝ 增量大小，而非数据集大小**；历史状态压缩在 manifest 里由脚本读取，模型不通读旧文件、不整表查询。

4. **端到端（用户侧）**：

   - 逆向模式：生成脚本 → 脚本在 `crawl_script/<站点键>/`、`index.md` 有登记；对需渲染站点生成脚本检查默认走 camoufox；
   - 工作流模式：建好一套 采集+提取 脚本后，说"增量更新 <站点>" → 应只跑两个 `--incremental` 命令并汇报新增/更新/跳过。

## 7. 注意事项与维护

- **站点键一致性**：采集/逆向/工作流与 manifest 共用同一站点键；改名会导致目录与 manifest 脱节，尽量不要改。
- **`dataDir` vs `saveDir`**：`crawl_fetch` 每次调用指定目录的参数名是 **`saveDir`**（插件级静态配置才是 `dataDir`）；persona/SKILL 已统一用 `saveDir`，勿混用。
- **manifest 为共享状态**：采集脚本写 `content_hash`/`file_hash`，提取脚本写 `extracted_hash`；两者顺序执行即可，不并发写。
- **历史数据**：没有 manifest 的旧数据首次 `--incremental` 会全量处理一次（UPSERT 去重安全）。
- **改模板**：改仓库源后需同步到 `C:/Users/ausu/.dsh/skills/<技能>/`；已生成的脚本是独立副本，不会自动更新，需重新生成或手动复制新模板。
- **合规**：尊重目标网站服务条款与反爬规则；只写用户授权库表；增量频率与范围保持合理。
