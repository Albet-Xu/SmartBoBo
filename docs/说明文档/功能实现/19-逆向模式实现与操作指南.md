# 19-逆向模式功能实现与操作指南

> 本文档记录 SmartBoBo「逆向模式」Agent 预设从构思到落地的**全部操作步骤、新增/修改的文件**，以及以后如何维护、如何验证。供后续自维护与排障定位。

---

## 1. 功能概述

在「Agent 预设」中新增 **逆向模式**：当用户输入含「采集 / 逆向 / 破解 / 爬取」等关键词且带有网址时，逆向模式会：

1. 提取用户输入中的网址；
2. 利用 **js-reverse** 等网页逆向 MCP 工具对目标网页/接口做逆向分析（定位接口、签名、加密、反爬点）；
3. 遇到难以自动跳过、需要用户提供信息（Cookie / Token / 验证码 / 目标字段等）的地方，**主动用 ask-user 询问用户**；
4. 复用内置模板技能 `reverse-crawler` 生成一份**结构完整、清晰**的 Python 爬虫脚本；
5. 脚本保存到**当前工作区**的 `crawl_script/` 目录（不存在则自动创建）；
6. 脚本采集到的数据以 **Markdown** 格式保存到当前工作区的 `data/` 目录（不存在则自动创建）；
7. AI 可自行运行脚本测试，但**最终返回给用户的是脚本代码**，而非采集到的数据——数据由用户自行运行脚本获得。

**核心特色（需求 3）**：爬虫脚本的公共骨架（文件保存、Markdown 转换、CLI 参数、请求重试、会话管理）被抽成**可复用模板**，AI 生成脚本时只实现该网站特有的采集逻辑，从而显著减少 token 消耗。

---

## 2. 设计定位

- 参考已有「采集模式（crawl）」的预设机制（纯提示词驱动 + 工具集配置）。
- 工具组成**接近标准模式**（shell、fs、skill、计划、子代理、web 等），让模型能自主选择合适工具完成逆向；与标准模式的区别仅在 personna 的行为目标——专注网页逆向与爬虫脚本生成。
- 生成脚本/数据都写到**用户当前打开的工作区**（`{{cwd}}`），而不是固定的 BoBo 根目录。

## 4. 各配置说明

### 4.1 预设配置文件 `preset.yml`

```yaml
name: 逆向模式
description: 识别用户输入中的采集/逆向/破解/爬取关键词与网址，用 js-reverse 等网页逆向工具分析网页与接口，并生成可复用、结构完整的 Python 爬虫脚本保存到当前工作区。
order: 6
```

- `name` / `description`：设置界面「Agent 预设」展示的名称与描述。
- `order`：显示顺序。现有顺序：standard=1, code=2, minimal=3, cordis=4, crawl=5，逆向模式排**采集模式之后（6）**。

### 4.2 预设组成 `agent.cordis.yml`

`persona`（`@deepseek-ai/dsh-persona`）定义了逆向模式的行为规则，核心段落：

- **触发与意图识别**：触发词（采集/逆向/破解/爬取/抓取/反爬/数据接口/写爬虫等）+ 网址；关键词无网址时用 ask-user 询问；无逆向意图时不触发。
- **网页逆向流程**：先用采集/抓包获取页面与网络请求 → 调用 `mcp__js-reverse__*` 分析接口/签名/加密/反爬 → 结合已安装的爬虫/逆向 skills 与 `reverse-crawler` 技能选方案。
- **主动询问用户**：遇到需要用户信息且难以自动跳过的环节，必须用 ask-user 询问（Cookie/Token/验证码/目标字段/代理等），不猜测不编造。
- **生成脚本**：加载 `reverse-crawler` 模板技能，复用 `crawl_template.py` 骨架。
- **保存脚本**：`{{cwd}}/crawl_script/<脚本名>.py`，缺目录自动创建。
- **数据输出**：脚本输出 Markdown，保存到 `{{cwd}}/data/`，缺目录自动创建。
- **交付方式**：可自测运行，但最终返回给用户的是脚本代码，不是采集数据。
- **品牌规则**：沿用 BoBo 身份话术（压制 MiMo）。

工具集（沿用标准模式的编码/逆向能力）：

- shell：`tool-bash`（非 Windows） / `tool-pwsh`（Windows）
- filesystem：`tool-fs`、`tool-fs-search`
- 后台任务：`tool-jobs`
- 技能：`skill-filesystem`、`tool-skill`
- 目标：`tool-goal`
- 计划：`planning`（`cordis:group` + `isolate.planMode`）
- 压缩：`compaction`（group）
- 委派/工作流：`delegation`（group，subagent / workflow）
- 交互：`tool-ask-user`、`tool-todo`
- 网页检索：`tool-web`（`fetch: false`，仅搜索）

### 4.3 模板技能 `reverse-crawler`

- 位置：`~/.dsh/skills/reverse-crawler/`（用户级，skill-filesystem 扫描，任意工作区可用）。
- `SKILL.md`：描述生成脚本的 SOP，强调"只改目标定制区、复用通用骨架、返回脚本而非数据"。
- `crawl_template.py`：可复用骨架，含 `build_parser`（CLI 参数）、`make_session`/`fetch`（会话+重试）、`html_to_markdown`（HTML→Markdown）、`save_markdown`（保存+建目录）、`build_filename`；`# ⛏️ TARGET-CUSTOM` 标记的 `build_default_url` / `prepare_request` / `parse_data` / `collect_all` 为**目标网站定制区**。

> 技能放用户级 `~/.dsh/skills/` 会出现在「技能库」中，这是预期选择（便于用户查看/管理），并已在 `skills.yaml` 登记。

### 4.4 js-reverse MCP 挂载

MCP 工具在 dsh 中需**两处写入**（与 Web 设置界面安装的机制一致）：

**① 挂载（真正启动插件）** —— `~/.dsh/cordis.patch.yml`（原本不存在，本次创建）：
```yaml
- id: mcp-js-reverse
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: js-reverse
    transport: stdio
    command: npx
    args:
      - '-y'
      - js-reverse
    toolCallTimeoutMs: 120000
    reconnect:
      enabled: true
      initialDelayMs: 500
      maxDelayMs: 30000
      maxAttempts: 10
```

**② 列表展示（「MCP 工具」页面可见）** —— `~/.dsh/settings.yaml` 追加 `mcp-tools` 命名空间：
```yaml
mcp-tools:
  tools:
    - id: js-reverse
      serverName: js-reverse
      transport: stdio
      command: npx
      args: ['-y', 'js-reverse']
      enabled: true
      toolCallTimeoutMs: 120000
      reconnect:
        enabled: true
        initialDelayMs: 500
        maxDelayMs: 30000
        maxAttempts: 10
```

> 说明：`~/.dsh/mcp-tools.yaml` 中原本已有 js-reverse 配置（历史遗留登记文件），但它**不是**真实挂载，真正起作用的挂载是 `cordis.patch.yml`。保留该文件不影响运行。

## 5. 如何生效

| 改动 | 生效方式 |
|---|---|
| 新建预设 `reverse/`（persona 与工具集） | `preset` 只在启动时加载，**重启**后在设置 → Agent 预设出现 |
| js-reverse MCP（`cordis.patch.yml`） | MCP 只在启动时挂载，**重启**后才可连接 |
| `skill-filesystem` 扫描的 `~/.dsh/skills/reverse-crawler/` | 技能发现**即时**，无需重启 |
| `skills.yaml` / `settings.yaml` | 热重载读取，UI 即时可见 |

**重启命令**：在 `BoBo/dsh/` 执行 `pnpm bobo`。

## 6. 验证方法

1. **预设可见**：进入 设置 → Agent 预设，应看到「逆向模式」（排在采集模式之后）。
2. **技能可加载**：进入 逆向模式，让模型加载技能目录 / 在「技能库」确认 `reverse-crawler` 存在且启用。
3. **MCP 已连接**：设置 → MCP 工具，`js-reverse` 显示已连接、工具计数 > 0（需重启后）。
4. **端到端**：在逆向模式发「逆向采集 https://某站点 xxx」，预期模型用 js-reverse 分析接口、必要时 ask-user 询问、生成脚本并保存到 `crawl_script/`；运行脚本后 Markdown 数据落在 `data/`。

## 7. 以后如何维护

### 改「逆向模式」行为/提示词

只改 `BoBo/dsh/apps/cli/config/agent-presets/reverse/agent.cordis.yml` 的 `persona`（`config.text`）。改完重启生效。关键词、保存路径、交付规则都在里面。

### 改「可复用模板」

改 `~/.dsh/skills/reverse-crawler/crawl_template.py`（骨架）与 `SKILL.md`（SOP/说明）。技能发现是即时热更，改动无需重启，但**已生成的脚本不受影响**（它们已是独立的 .py 副本）。

### 调整 js-reverse

- 启停：设置 → MCP 工具 → 开关 js-reverse（会增删 `cordis.patch.yml` 的对应行，下次重启生效）。
- 换 MCP 服务器：按 4.4 的格式替换 serverName / command / args。

---

## 8. 注意事项

- 逆向模式默认工作区 = **打开 BoBo 时所在目录**（`{{cwd}}`）；脚本与数据都写在该工作区的 `crawl_script/`、`data/`，不会写入 BoBo 根目录。
- 依赖：生成的脚本默认依赖 `requests`（模板 `__main__` 会提示安装）；需 html2text 时可选安装。
- 合规：模板与 persona 均要求不用于非法、绕过付费墙、损害他人系统的用途。
- `agent.cordis.yml` 与 `preset.yml` 语法已校验通过；`!!js` 是 dsh 自定义标签，勿用普通 YAML 解析器校验其语义。

## 9. 技能库数据源统一（补充修订）

### 9.1 背景：曾存在两个技能库数据源

- `~/.dsh/skills.yaml`（遗留文件）：登记了 `summarize`、`reverse-crawler`，**代码不读取它**（全项目 `grep "skills.yaml"` 仅命中文档示例，无任何代码引用）。
- `~/.dsh/settings.yaml` 的 `skill-library` 命名空间：**真实数据源**。前端「技能库」(`ui-settings-skills`) 与后台 `api-proxy` 的 `skillLibrary` 域（安装/开关/卸载/分组）都读写它。

### 9.2 处置

删除遗留源 **`~/.dsh/skills.yaml`**（0 代码改动），把两个技能登记**迁移到 `settings.yaml` 的 `skill-library`**。迁移前 `skills.yaml` 原文（备份参照）：

```yaml
skills:
  - name: summarize
    description: 内容摘要总结技能，能够对长文本、网页、文档进行智能摘要。
    source: local
    path: ~/.dsh/skills/summarize/SKILL.md
    enabled: true
    invocation: { modelInvocable: true, userInvocable: true }
  - name: reverse-crawler
    description: 网页逆向后复用生成 Python 爬虫脚本的模板：Markdown 保存、CLI 参数、请求重试、会话管理骨架与逆向 SOP。
    source: local
    path: ~/.dsh/skills/reverse-crawler/SKILL.md
    enabled: true
    invocation: { modelInvocable: true, userInvocable: true }
```

迁移后 `settings.yaml` 新增命名空间（`group` 用 `null`，`path` 用**绝对路径**，便于前端卸载时定位删除目录）：

```yaml
skill-library:
  groups: []
  skills:
    - name: summarize
      description: 内容摘要总结技能，能够对长文本、网页、文档进行智能摘要。
      source: local
      enabled: true
      group: null
      path: C:/Users/Albet/.dsh/skills/summarize/SKILL.md
    - name: reverse-crawler
      description: 网页逆向后复用生成 Python 爬虫脚本的模板：Markdown 保存、CLI 参数、请求重试、会话管理骨架与逆向 SOP。
      source: local
      enabled: true
      group: null
      path: C:/Users/Albet/.dsh/skills/reverse-crawler/SKILL.md
```

### 9.3 效果

- 技能库**唯一数据源** = `settings.yaml` 的 `skill-library`。前端安装 / 开关 / 卸载 / 分组都正常读写它，增删改即刻生效（settings 热重载）。
- 技能实体文件仍在发现目录 `~/.dsh/skills/`，`skill-filesystem` 实时发现。

### 9.4 「新增模式能加载技能库技能」的约定

技能能否被 AI 调用，取决于两件事：
1. 技能实体文件在发现目录（`~/.dsh/skills/` 或项目 `.agents/skills/`）；
2. 当前会话所在预设**挂了技能能力**（`skill-filesystem` + `tool-skill` 两行）。

- **内置模式保持原样**：standard(order1)/PTC(order2)/极简(order3)/创造(order4) 及采集模式(order5) 的能力**不做改动**；其中极简/采集模式原本**不含**技能能力。
- **`reverse`（order6，本次新增）已包含** `skill-filesystem` + `tool-skill`，可加载技能库 skill。
- **今后新增预设**：验收标准 = 在 `agent.cordis.yml` 中显式加入 `skill-filesystem` 与 `tool-skill` 两行，否则模型无法加载技能库里的技能。
