# 25-新会话创建失败修复操作指南

> 本指南记录「工作区无法选中 / 点击新会话无法新建会话」问题的根因、修复步骤、验证方法与涉及文件清单。

---

## 一、问题现象

在 BoBo Web 界面（`bobo` 启动的 dsh web，端口 7070）中：

1. 点击侧边栏「新会话」按钮，无法新建会话，界面无任何反应。
2. 点击/选中某个工作区，同样无法打开会话，界面无反应。

前端对建会话失败只是 `console.warn` 静默处理，因此表现为「点了没反应」，不报任何错误。

---

## 二、根因分析

### 1. 会话创建链路

点「新会话」或选中工作区，都会进入同一条链路：

```
startSession() → workspaces.connectWorkspace() → sessions.create()
    → 前端 RPC session.create → host 装配默认 Agent 预设 → 返回 sessionId
```

- 默认预设来自 `~/.dsh/settings.yaml` 的 `agent-presets.default = crawl`。
- `crawl` 预设 `dsh/apps/cli/config/agent-presets/crawl/agent.cordis.yml` 装配了 `/proxy` 命令插件：
  ```yaml
  - id: command-proxy
    name: '@deepseek-ai/dsh-command-proxy'
  ```

### 2. 真正的故障点：宿主插件未注册为可解析依赖

`@deepseek-ai/dsh-command-proxy` 是**宿主插件**，只以 cordis 裸插件行被预设引用，同时被 `tsconfig.host.json` 加入构建引用（所以 `pnpm run build` 能通过）。但：

- 它**没有**被任何包的 `dependencies`/`devDependencies` 声明；
- pnpm 只为「被某包依赖」的包建立 `dsh/node_modules/@deepseek-ai/` 链接；
- 因此 `@deepseek-ai/dsh-command-proxy` 不在 `node_modules` 中，运行时装配预设 `crawl` 时 `import` 失败 → 预设挂载失败 → `session.create` 返回 `agent-preset-invalid`。

### 3. 实测复现的错误

对运行中的后端发起 `session.create`，修复前返回：

```json
{ "ok": false, "error": {
  "code": "agent-preset-invalid",
  "message": "agent-presets: preset \"crawl\" failed to mount: failed to import loader entry
  command-proxy (@deepseek-ai/dsh-command-proxy):
  Cannot find package '@deepseek-ai/dsh-command-proxy'
  imported from C:\\Users\\ausu\\.dsh\\profiles\\web\\ ..." } }
```

### 4. 对照结论

- 远程 `github/bobo-version-01`（= 本地 `bobo-version-01`，`895db1dc`）**不含**代理特性（无 `packages/proxy/`、无 `command-proxy`），会话创建正常。
- 本问题由 bobo-version-02 引入的代理特性「接线遗漏」造成：预设与构建引用了插件，但宿主 bundle/CLI 的依赖清单未登记该包。
- 两个界面问题（工作区选中 + 新建会话）本质同因，因为它们共用 `session.create` 这条路径。

---

## 三、修改文件清单

| 文件 | 修改内容 |
|---|---|
| `dsh/package.json`（workspace 根） | `devDependencies` 新增 `"@deepseek-ai/dsh-command-proxy": "workspace:^"` |
| `dsh/apps/cli/package.json` | `dependencies` 新增 `"@deepseek-ai/dsh-command-proxy": "workspace:^"` |

> 参照先例：同是被 agent 预设装配的宿主插件 `@deepseek-ai/dsh-tool-acquisition`，也声明在根 `package.json`（devDependencies）与 `apps/cli/package.json`（dependencies），从而被 pnpm 链接到根 `node_modules` 并在运行期解析成功。命令代理按完全相同的方式补齐。

---

## 四、修复步骤

1. 在 `dsh/package.json` 的 `devDependencies`（`dsh-tool-acquisition` 条目旁）新增：
   ```json
   "@deepseek-ai/dsh-command-proxy": "workspace:^",
   ```
2. 在 `dsh/apps/cli/package.json` 的 `dependencies`（`dsh-tool-acquisition` 条目旁）新增同一条目。
3. 安装依赖，建立 `node_modules` 链接：
   ```bash
   cd dsh
   pnpm install
   ```
   校验链接存在：
   ```bash
   ls -l dsh/node_modules/@deepseek-ai/dsh-command-proxy
   # -> /path/to/dsh/packages/proxy/command-proxy
   ```
4. 重启 BoBo 后端（`bobo`）使其生效。

---

## 五、验证方法

1. 确认后端已启动并监听 7070：
   ```bash
   curl -s -m 4 -o /dev/null -w "HTTP %{http_code}\n" http://127.0.0.1:7070/
   # HTTP 200
   ```
2. 发起建会话 RPC（`WORKSPACE_ID` 换成你的工作区 id，可在 `~/.dsh/storages/workspace.json` 查看）：
   ```bash
   WSID="<workspace-id>"
   RID=$(python -c "import uuid;print(uuid.uuid4())")
   curl -s -m 40 -X POST "http://127.0.0.1:7070/api/session.create" \
     -H 'content-type: application/json' \
     -d "{\"type\":\"client-request\",\"rpcId\":\"$RID\",\"method\":\"session.create\",\"payload\":{\"workspaceId\":\"$WSID\"}}"
   ```
3. 修复前返回 `agent-preset-invalid`；修复后应返回：
   ```json
   { "ok": true, "value": { "sessionId": "session-xxxxxxxx-...", "agentPreset": "crawl" } }
   ```

---

## 六、涉及行为说明

- 前端 `dsh/packages/client/runtime/src/client/workspaces/service.ts` 的 `connectWorkspace()` 在找不到可复用空白会话时会调用 `sessions.create()`；失败仅 `console.warn('new session failed', reason)`，故界面无提示。这是「点了没反应」的直接原因。
- 修复后，点「新会话」、选中/打开工作区均可正常创建并挂载 `crawl` 预设会话。

---

## 七、注意事项

1. **首次排查提示**：若界面「点了没反应」，优先看后端日志/实测 RPC，前端会吞掉建会话错误。
2. 本次修改已落在工作区；换新机器部署或重建环境后，需重新执行 `pnpm install`，否则 `node_modules` 中不会出现该包。
3. 验证过程中若产生了测试空白会话，可在界面中删除，不影响数据。
4. `tsconfig.host.json` 中的 `command-proxy` 构建引用已存在，无需改动（那是编译期，本次补的是运行期依赖解析）。
