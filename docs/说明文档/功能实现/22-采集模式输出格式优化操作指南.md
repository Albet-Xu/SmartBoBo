# 采集模式输出格式优化操作指南

## 1. 优化目标

采集模式（crawl 预设）此前把抓取到的网页内容**固定转换成 Markdown（.md）**并落盘。本次优化让**用户可以选择采集结果的输出格式**，且支持**一次抓取、产出多种格式**（以同一份渲染后 HTML 为素材，分别派生）：

| 输出格式 | 说明 | 扩展名 | 转换方式 |
|----------|------|--------|----------|
| `html`   | 渲染后的原始 HTML | `.html` | 原样输出（不转换） |
| `md`     | Markdown（默认） | `.md` | `html2text` |
| `skeleton` | 网页块级骨架 | `.skeleton.txt` | `lxml`（沿用 `aaa.py` 的生成逻辑） |

选择规则：
- **一种格式**：用户指定 `html` / `md` / `skeleton` 之一 → 只输出该格式。
- **多种格式**：用户一次要多份（如"md、html 和网页骨架"）→ 逗号分隔请求（`html,md,skeleton`），**只抓一次网页**，同一份渲染 HTML 分别派生各格式文件。
- **未指定**：默认只输出 `md`。

## 2. 优化思路

核心是"**采集只抓一次渲染后的 HTML，再按用户选择的 `outputFormat` 决定怎么落盘**"，并把"格式转换 + 命名 + 落盘 + 回 JSON"抽成一份共享模块，避免三个引擎脚本各自维护重复逻辑。

```
用户输入"采集 X" / "存成 html" / "要 md、html 和网页骨架"
  → crawl Persona 识别 URL + 输出格式意图
  → crawl_fetch(url, outputFormat='html' | 'md,html,skeleton')
  → tool-acquisition 插件拼参数 --format <格式串> 调脚本（只调一次）
  → run_<engine>.py：
        抓取渲染 HTML（1 次）
        → html 格式直接存 .html
        → 其余格式从这份 HTML 派生（md→html2text，skeleton→lxml）
        同一基座文件名，各格式带各自扩展名
  → stdout 单行 JSON {savedTo,status,preview,title,format,outputs:[{format,path}]}
  → 汇报：须列出所有产物路径 + HTTP 状态 + 格式 + 摘要
```

## 3. 涉及文件

### 3.1 新增文件

- `BoBo/scripts/skeleton_gen.py` —— 网页块级骨架生成**纯函数模块**（lxml），由项目根 `aaa.py` 的核心逻辑抽取（`BLOCK_TAGS`/`NOISE_TAGS`/`build_selector`/`get_full_path`/`process`/`clean_skeleton`），对外暴露 `html_to_skeleton(html_str)`。去掉 `aaa.py` 里的文件读取/URL 抓取/落盘 IO。
- `BoBo/scripts/crawl_common.py` —— 三引擎脚本共享的转换与落盘工具：
  - `FORMAT_EXT`：格式 → 扩展名（`html:.html`、`md:.md`、`skeleton:.skeleton.txt`）、`DEFAULT_FORMAT='md'`
  - `parse_formats(format_arg)`：把逗号分隔请求解析成去重、保序的格式列表；空/全非法回退 `['md']`
  - `make_html2text()` / `html_to_format(html, fmt)`：格式转换（html 原样/md html2text/skeleton lxml）
  - `resolve_outputs(out, url, title, fmt_list, auto_name)`：多格式统一命名——同一基座 `站点_标题_时间戳`，各格式各附扩展名
  - `write_output(out_path, content)`：UTF-8 落盘

### 3.2 修改文件

- `BoBo/pyproject.toml` —— 显式声明 `lxml>=5.3.0`（骨架生成依赖，沿用 aaa.py 解析栈）。改后需 `uv sync`。
- `BoBo/scripts/run_camoufox.py` / `run_scrapling.py` / `run_crawl4ai.py` —— `--format` 改为**逗号分隔多格式**，一次抓取循环派生各格式落盘，返回 `outputs` 产物列表；各自的抓取流程（camoufox 渲染+滚轮+去 cookie 弹窗、scrapling fetch、crawl4ai arun）保持不变。
- `BoBo/dsh/packages/acquisition/tool-acquisition/src/index.ts` —— `crawl_fetch` 新增 `outputFormat`（逗号分隔多选）并透传 `--format`；返回新增 `outputs: [{format,path}]`；未知格式项被剔除、重复项去重、全非法回退 `md`。
- `BoBo/dsh/apps/cli/config/agent-presets/crawl/agent.cordis.yml` —— Persona 新增"输出格式选择"规则：识别单格式或"多种格式"意图并传 `outputFormat`；未指定用默认 `md`；汇报列出全部产物路径与格式。

## 4. 使用示例

| 用户输入 | 采集次数 | 产物 |
|----------|----------|------|
| `采集 https://example.com/a` | 1 | `.md`（默认） |
| `采集 https://example.com/a 存成 html` | 1 | `.html` |
| `采集 https://example.com/a 输出骨架` | 1 | `.skeleton.txt` |
| `请帮我采集这个网页，输出格式需要 md、html 和网页骨架` | **1** | `.html` + `.md` + `.skeleton.txt`（同基座名） |

多格式产物示例（一次抓取派生）：

```
example.com_标题_20260825-101010.html
example.com_标题_20260825-101010.md
example.com_标题_20260825-101010.skeleton.txt
```

骨架（skeleton）内容示例（每行一个含直接文本的块级容器）：

```
div#main.article > h1 -> 标题文本
div#main.article > section.body > p -> 第一段正文
div#main.article > section.body > p -> 第二段正文
```

### 5.1 构建与依赖

```bash
cd E:/SmartBoBo/BoBo
```

### 5.2 Python 脚本直测（多格式一次抓取）

```bash
cd E:/SmartBoBo/BoBo
# 一次抓取产三种格式
./.venv/Scripts/python.exe scripts/run_scrapling.py \
  --url https://example.com --out data/test --format html,md,skeleton --auto-name
./.venv/Scripts/python.exe scripts/run_camoufox.py \
  --url https://example.com --out data/test --format html --auto-name
```

检查：产出 .html + .md + .skeleton.txt（同基座名）；stdio 只输出一行 JSON，含 `outputs: [{format,path}]`。

### 5.3 平台内联验证

在采集模式分别输入：
1. 仅 URL（不指定格式）→ 只输出 `.md`（不破坏旧行为）；
2. `输出格式需要 md、html 和网页骨架` → **只发起一次采集**，得到 3 个文件；
3. 指定非法格式 → 回退为 `md`。

## 6. 注意事项

- **多格式不额外抓取**：`html,md,skeleton` 只抓一次网页，md/skeleton 均由那份渲染后 HTML 派生。
- **skeleton 依赖 `lxml`**：`.venv` 已安装（v6.1.x）；换机器先 `uv sync`。
- **预览**：回给插件的 `preview` 是页面正文纯文本摘要，不随输出格式变化，仅作汇报告知。
- **crawl4ai 引擎的 md**：优先用 Crawl4AI 自带 Markdown，不可用时回退 `html2text`；`html`/`skeleton` 走统一转换。
- **扩展名补全**：非 auto-name 时，脚本以调用方路径为基座，逐个格式追加深扩展名；同一基座避免重复抓取。
