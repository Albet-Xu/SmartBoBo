# 21-工作流模式实现与操作指南

> 本文档记录 SmartBoBo「工作流模式」Agent 预设的**全部新增/修改文件、工作原理、如何生效、如何验证、后续如何维护**，供后续自维护与排障定位。

---

## 1. 功能概述

在「Agent 预设」中新增 **工作流模式**：当用户输入含「采集 / 爬取 / 入库 / 存表」等关键词且带有网址（或数据库目标）时，工作流模式会：

1. **读取数据库字段（只针对被授权的目标表）**：读取 DBX 面板已保存的连接（`dbx-runtime/data/dbx.db`），目标库已有连接则直接复用；没有则询问用户或引导其在「数据库」面板新建；**直接 `describe-table` 目标表读取全部字段（不用 `list-tables` 枚举其它表）**；用户给的参考表仅只读参考，绝不写入；空白/新表则询问 CREATE TABLE SQL 或逐个定义字段；
2. **确认字段含义（严格逐一）**：把目标表全部字段**逐个字段**用 ask_user 询问含义与数据来源（每问完一个再问下一个），每个字段都可给**推荐方案**（含 NOT NULL 配置类字段的建议默认值），但**必须保证每个字段都征求过用户的意见**；不擅自猜测写入；
3. **抓样品页了解结构**：抓一个样品页，阅读并**枚举该网页能提供哪些信息点**（标题 / 正文 / 列表 / 价格 / 日期 / 链接等）与样例值；同时检查 `crawl_script/` 是否已有匹配的逆向脚本；
4. **核对字段满足度 & 补空值/固定值**：把已确认的每个字段逐一对照样品页——能提取的标记来源；**页面满足不了的字段逐个询问用户**：填 NULL 空值，还是给固定值；整理最终映射再确认一次；
5. **写提取入库脚本**：把确认好的字段映射沉淀成 Python 提取入库脚本，保存到**当前工作区 `extraction_scripts/`**（不存在则自动创建）；同类型网址 + 同目标表直接复用已有脚本；
6. **批量采集与入库（采集/入库分离，只写目标表）**：批量来源可为输入 URL、URL 清单文件或已抓好的 `data/` 目录；先批量采集（逆向脚本或 `crawl_fetch` 按引擎降级）落 `data/`，再调用脚本 `--data data` 批量 UPSERT（已存在更新、不存在插入），**只写入目标表**；写入前先 dry-run 预览给你确认。

**核心特色**：提取脚本的公共骨架（读数据、取字段、连库、UPSERT、预览、CLI 参数）被抽成**可复用模板**（`extraction_template.py` + `dbx_connector.py`），AI 生成脚本时只填「# ⛏️ GEN-CUSTOM」定制区，从而显著减少 token 消耗。

## 3. 各配置说明

### 3.1 预设元数据 `preset.yml`

```yaml
name: 工作流模式
description: 识别用户输入中的采集/爬取关键词与网址，自动采集（或复用逆向脚本）数据到当前工作区，检索并复用内置 DBX 已保存的数据库连接，逐字段向用户确认含义后，复用模板生成 Python 提取入库脚本（UPSERT 去重/更新入库），保存到工作区 extraction_scripts 目录。
order: 7
```

- `order: 7`：现有顺序 standard=1, code=2, minimal=3, cordis=4, crawl(采集)=5, reverse(逆向)=6，工作流排在逆向之后。

### 3.2 预设组成 `agent.cordis.yml`

`persona`（`@deepseek-ai/dsh-persona`）定义了工作流模式的行为规则，核心是**六阶段 SOP**：

1. **触发与意图识别**：触发词（采集/爬取/抓取/入库/存表/写入数据库/存数据）+ 网址或数据库目标；无关请求不触发。
2. **读取数据库字段（只针对被授权的目标表）**：**先定位 BoBo 根目录**（含 `dbx-runtime` 的目录，常见 `E:/SmartBoBo/BoBo`、`~/SmartBoBo/BoBo`）；加载 `db-extraction` 技能用 `dbx_connector --bo-bo-root <根目录>` 确认并复用 DBX 已存连接（**必须带 `--bo-bo-root`**，否则在工作区找不到 `dbx.db`）；**直接 `describe-table` 目标表**校验存在并取全部字段（**不用 `list-tables` 枚举其它表**）；用户给的参考表仅只读参考、绝不写入；空白/新表询问 CREATE TABLE SQL 或逐字段定义、仅建目标表。
3. **确认字段含义（严格逐一，不猜测入库）**：拿到目标表全部字段后**严格逐一**用 ask_user 逐个字段询问含义与数据来源（每问完一个再问下一个）；**必须保证每个字段都征求过用户意见**；每个字段可给**推荐方案**（含 NOT NULL 配置类字段的建议默认值），但推荐不能代替询问；先只确认字段含义。
4. **抓样品页了解结构**：抓一个样品页（`crawl_fetch` 或先跑已有逆向脚本），阅读并枚举该网页能提供哪些信息点与样例值；同时检查 `crawl_script/` 有无匹配脚本（留到批量采集阶段优先调用）。
5. **核对字段满足度 & 补空值/固定值**：把已确认的每个字段逐一对照样品页，能提取的标记来源；**页面满足不了的字段逐个询问用户**填 NULL 还是固定值；整理最终映射再让用户确认一次。
6. **写提取脚本并批量入库**：查 `extraction_scripts/index.md` 复用已有脚本；否则复制 `extraction_template.py` 只填 GEN-CUSTOM 区（`CONFIG.dbx_data_dir` 填 `<根目录>/dbx-runtime/data`）；然后**采集/入库分离**——对大批量同类型网址（输入 URL / URL 清单文件 / 已有 `data/` 目录）先批量采集（逆向脚本或 `crawl_fetch` 按引擎降级）落 `data/`，再 `python <脚本> --data data`（或 `--urls <清单> --data-dir data`）批量 UPSERT；dry-run 预览 → 确认 → 只写目标表 → 汇报插入/更新条数。

工具集（沿用逆向模式的近标准工具 + 采集工具）：

- 采集：`tool-acquisition`（`crawl_fetch`，默认存当前工作区 `data/`）
- shell：`tool-bash`（非 Windows）/ `tool-pwsh`（Windows）
- filesystem：`tool-fs`、`tool-fs-search`
- 后台任务：`tool-jobs`
- 技能：`skill-filesystem`、`tool-skill`
- 目标：`tool-goal`
- 计划：`planning`（isolate.planMode）
- 压缩：`compaction`
- 委派/工作流：`delegation`（subagent / workflow）
- 交互：`tool-ask-user`、`tool-todo`
- 网页检索：`tool-web`（`fetch: false`）

### 3.3 模板技能 `db-extraction`

- 位置：`~/.dsh/skills/db-extraction/`（用户级，`skill-filesystem` 扫描，任意工作区可用；已在 `settings.yaml` 的 `skill-library` 登记）。
- `SKILL.md`：提取入库 SOP，强调"逐字段确认、复用模板、UPSERT 去重、预览后再写库、写入固定值/空值策略"。
- `dbx_connector.py`：**数据库连接底层库**，也作为 CLI 使用：
  - 定位 BoBo 根目录（含 `dbx-runtime` 的目录）：优先环境变量 `BOBO_ROOT` → 从当前目录向上找 → **常见安装位置兜底**（`C:/D:/E:/` 下的 `SmartBoBo/BoBo`、`BoBo` 及 `~/SmartBoBo/BoBo`）；在工作区无法命中时请显式带 `--bo-bo-root <根目录>`；
  - `list-connections` / `list-tables <连接名>` / `describe-table <连接名> <表名>` / `table-exists`；
  - `upsert_rows(profile, table, rows, unique_keys)`：**UPSERT 去重/更新**（先按唯一键 UPDATE，未命中再 INSERT，跨库计数准确）；去重键为空时自动取表主键（描述 `key==PRI`），仍无则退化为追加插入；
  - 数据源：读 `dbx-runtime/data/dbx.db` 的 `connections` + `connection_secrets`，据此复用 DBX 面板已保存的连接（MySQL/PostgreSQL/SQLite，按 db_type 选驱动；缺失驱动会给出安装命令）。
- `extraction_template.py`：**可复用提取入库骨架**。含 `CONFIG`（连接名/目标表/dbx_data_dir/输入/去重键/固定值）、`extract_rows()`（目标网站特有解析，`# ⛏️ GEN-CUSTOM`）、通用 CLI（`--dry-run` 预览 / 正式入库 / `--limit` 等）、字段清洗、固定值/空值补齐、本地去重。

> 关键点：生成的提取脚本会把 `dbx_connector.py` 一并复制到 `extraction_scripts/`，从而**独立于技能目录运行**、可被同类网址复用。

### 3.4 依赖与驱动

`BoBo/pyproject.toml` 新增：

```toml
"pymysql>=1.1.0",      # MySQL / MariaDB
"psycopg[binary]>=3.2.0",  # PostgreSQL
```

经 `uv sync` 装进 `.venv`（sqlite3 为标准库，无需安装）。运行提取脚本**建议用 BoBo 的 `.venv/Scripts/python.exe`**；用系统 python 缺驱动时脚本会打印安装命令。

## 5. 工作流端到端示例

**用户输入**：`把 https://example.com/books 的书单采集下来，存到 MySQL_tloz 的 book 表`

**预期行为**：

1. 识别采集关键词 + 网址 → 读取库字段（只针对目标表）：`dbx_connector --bo-bo-root <根目录> list-connections` 确认连接 `MySQL_tloz` 并复用；`describe-table book`（**跳过 `list-tables`**）校验 `book` 表存在并读取其全部字段。
2. **严格逐一**用 ask_user 逐个确认 `book` 表每个字段的含义，每问完一个再问下一个；每个字段给推荐方案，但**每个字段都征求用户意见**（此步先只确认含义）。
3. 抓一个样品页阅读，**枚举网页有哪些信息点**（书名 / 作者 / 价格 / 简介等）与样例值；同时检查 `crawl_script/` 有无匹配该站的逆向脚本。
4. 把每个字段对照样品页核对能否提取；**页面满足不了的字段逐个询问用户**填 NULL 还是固定值；整理最终映射再让用户确认一次。
5. 检查 `extraction_scripts/index.md`；无现成脚本则复制 `extraction_template.py` 生成 `extract_book.py`（只填 GEN-CUSTOM，`CONFIG.dbx_data_dir` 填 `<根目录>/dbx-runtime/data`），并复制 `dbx_connector.py`，登记进 index.md。
6. **批量采集与入库**：对大批量同类型网址（输入 URL / URL 清单文件 / 已有 `data/`）先批量采集落 `data/`（逆向脚本或 `crawl_fetch` 引擎降级）；`python extract_book.py --data data --dry-run` 预览待写入行 → 用户确认 → `python extract_book.py --data data` → **只向 `book` 表** UPSERT 入库 → 汇报插入/更新条数。

## 7. 以后如何维护

### 改「工作流模式」行为/提示词

只改 `BoBo/dsh/apps/cli/config/agent-presets/workflow/agent.cordis.yml` 的 `persona`（`config.text`）。改完重启生效。触发词、保存路径、六阶段 SOP、交付规则都在里面。

### 改「可复用模板/连接库」

改 `~/.dsh/skills/db-extraction/` 下的 `SKILL.md`（SOP）、`extraction_template.py`（骨架）、`dbx_connector.py`（连库/upsert）。技能发现即时热更，改动无需重启；**已生成的脚本不受影响**（它们是独立的 .py 副本，若需更新脚本需重新生成或手动复制新模板）。

### 调整连接源 / 驱动

- DBX 连接由用户在「数据库」面板维护，工作流模式读取其中已保存连接；新数据库类型需在 `dbx_connector.py` 的 `_CONNECTORS` 注册驱动。
- 第三方驱动安装：`cd BoBo && uv add <驱动>` 或临时 `pip install`；缺驱动时脚本会打印安装命令。

## 8. 注意事项

- 工作流默认工作区 = 打开 BoBo 时所在目录（`{{cwd}}`）；采集数据在 `data/`、提取脚本在 `extraction_scripts/`、逆向脚本在 `crawl_script/`，都不写入 BoBo 根目录。
- **授权范围（强制）**：只操作用户明确给出的目标表；用户给的参考表仅只读参考、绝不写入；不用 `list-tables` 枚举库里其它表；相关工具调用都带 `--bo-bo-root <根目录>`。
- **字段确认（严格逐一）**：目标表每个字段都用 ask_user 逐一询问含义，推荐方案可给但不能代替询问，保证每个字段都征求用户意见。
- 写库前必须 dry-run 预览并获用户确认；数据库写入仅限用户授权库表。
- 去重键缺失且表无主键时退化为追加插入，汇报里会说明。
- `agent.cordis.yml` 用 `!!js`（dsh 自定义标签，勿用普通 YAML 解析器校验语义）；`preset.yml`/`settings.yaml` 为纯 YAML。
- 合规：尊重目标网站服务条款与反爬规则，只写用户授权库表，对采集频率、范围与用途保持合理与合规。

## 9. 常见问题排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 工作流加载技能后就不再继续 / 回合中断 | 通常发生在 AI 要执行 shell 命令（如 pwsh 跑 `dbx_connector`）时触发了审批却未获批准，或模型调用异常 | 确认审批框是否弹出并放行；AI 应"执行前先说明将运行的命令"；若不弹框请检查会话审批策略 |
| `dbx_connector` 报"未定位到 BoBo 项目目录 / 找不到 dbx.db" | 工作区（如 `D:/Albet`）与 BoBo 安装目录（如 `E:/SmartBoBo/BoBo`）不在同一目录树，向上查找命中不了 | 所有 `dbx_connector` 命令带 `--bo-bo-root <BoBo根目录>`；提取脚本 `CONFIG.dbx_data_dir` 填 `<根目录>/dbx-runtime/data`；或用带兜底的版本自动探测 |
| 某个网址采集为空 / 超时 | 默认引擎 camoufox 对该站失败（TLS、反爬、慢） | 让 AI 自动降级改 `scrapling`（静态列表页快而稳），再失败改 `crawl4ai` |
| 入库报 `Column 'xxx' cannot be null` | 目标表字段为 `NOT NULL` 而映射没给值 | 对配置类字段使用建议默认值（`fetcher/per_column_limit/dedupe_enabled/sort_order/enabled/remark/created_at/updated_at`），用户确认后写入 |
| 工作流去枚举/读写了未授权表，或一次性批量确认字段 | 行为偏离"只动授权目标表 / 严格逐一确认" | 严格遵守：只 `describe-table` 目标表（参考表只读）、不用 `list-tables`；每个字段单独 ask_user 确认，推荐方案不能代替询问 |
| 写入中文乱码 | 网站编码被误判（如部分站 requests 判成 ISO-8859-1） | 用引擎输出（如 scrapling/camoufox 已按实际编码处理）；观察 `apparent_encoding`，必要时在提取脚本中按 `utf-8`/`gbk` 显式解码 |
