# 多模型支持配置指南

## 背景说明

当前 BoBo 平台默认使用 **DeepSeek 官方适配器** (`llm-deepseek`)，仅支持 DeepSeek 模型。如果你希望使用其他大模型（如 OpenAI、Claude、Gemini 等），需要切换到 **多模型适配器** (`llm-pi-ai`)。

---

## 方案一：继续使用 DeepSeek（修复当前问题）

### 适用场景
- 你已经有 DeepSeek API Key
- 你希望使用 DeepSeek-V4-Flash 或 V4-Pro 模型

### 问题诊断

当前报错：
```
llm-deepseek: the API key resolved from DEEPSEEK_API_KEY contains characters 
no HTTP header can carry
```

**原因：** `.env` 文件中包含了中文字符或其他非法字符。

### 修复步骤

#### 1. 编辑 `.env` 文件

文件位置：`E:\SmartBoBo\dsh\.env`

**错误示例**（包含中文）：
```env
DEEPSEEK_API_KEY=你的 DeepSeek API Key  ❌
```

**正确格式**（仅英文）：
```env
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
```

#### 2. 获取 DeepSeek API Key

1. 访问 DeepSeek 开放平台：https://platform.deepseek.com/
2. 登录/注册账号
3. 进入 **API Keys** 管理页面
4. 创建新的 API Key 或复制现有的
5. Key 格式：`sk-` 开头，后跟字母数字组合

#### 3. 清理 Key 中的非法字符

确保 Key 中**不包含**：
- ❌ 空格（前后都不要有）
- ❌ 换行符
- ❌ 制表符
- ❌ 中文字符
- ❌ 引号

**验证方法**（PowerShell）：
```powershell
$key = "sk-你的 Key"
$key -match '^[\x21-\x7E]+$'  # 应返回 True
```

#### 4. 重启服务

```cmd
cd E:\SmartBoBo
启动.cmd
```

#### 5. 验证配置

访问 http://127.0.0.1:7070，发送测试消息：
```
你好，请介绍一下你自己
```

## 方案二：切换到其他模型提供商（推荐）

### 适用场景
- 你想使用 OpenAI、Claude、Gemini 等其他模型
- 你有多个模型的 API Key，希望灵活切换

### 架构说明

`llm-pi-ai` 适配器支持以下协议：
- **OpenAI 兼容**（OpenAI、DeepSeek、Moonshot、零一万物等）
- **Anthropic**（Claude 系列）
- **Google AI**（Gemini 系列）
- **Azure OpenAI**
- **AWS Bedrock**

### 配置步骤

#### 1. 修改 dsh 配置文件

编辑文件：`E:\SmartBoBo\dsh\cordis.yml`

**当前配置**（可能类似）：
```yaml
- id: llm-deepseek
  name: '@deepseek-ai/dsh-llm-deepseek'
  config:
    apiKeyEnv: DEEPSEEK_API_KEY
```

**修改为**（添加 pi-ai 适配器）：
```yaml
# 注释掉原来的 deepseek 适配器
# - id: llm-deepseek
#   name: '@deepseek-ai/dsh-llm-deepseek'
#   config:
#     apiKeyEnv: DEEPSEEK_API_KEY

# 添加 pi-ai 多模型适配器
- id: llm
  name: '@deepseek-ai/dsh-llm-pi-ai'
  config:
    providers:
      # OpenAI
      openai:
        apiKeyEnv: OPENAI_API_KEY
      # Anthropic (Claude)
      anthropic:
        apiKeyEnv: ANTHROPIC_API_KEY
      # DeepSeek（仍然支持）
      deepseek:
        apiKeyEnv: DEEPSEEK_API_KEY
      # Google (Gemini)
      google:
        apiKeyEnv: GOOGLE_API_KEY
      # Moonshot (Kimi)
      moonshot:
        apiKeyEnv: MOONSHOT_API_KEY
```

#### 2. 创建新的 `.env` 文件

编辑文件：`E:\SmartBoBo\dsh\.env`

```env
# 选择你需要的模型提供商，填入对应的 API Key
# 不需要的可以注释掉或删除

# OpenAI（GPT-4、GPT-3.5 等）
OPENAI_API_KEY=sk-你的 OpenAI Key

# Anthropic（Claude 3.5、Claude 3 等）
ANTHROPIC_API_KEY=sk-ant-你的 Anthropic Key

# DeepSeek（V4-Flash、V4-Pro）
DEEPSEEK_API_KEY=sk-你的 DeepSeek Key

# Google（Gemini 1.5、Gemini 2.0）
GOOGLE_API_KEY=你的 Google Key

# Moonshot（Kimi）
MOONSHOT_API_KEY=sk-你的 Moonshot Key
```

#### 3. 获取各平台 API Key

| 平台 | 获取地址 | 备注 |
|------|----------|------|
| **OpenAI** | https://platform.openai.com/api-keys | 需要海外支付方式 |
| **Anthropic** | https://console.anthropic.com/settings/keys | Claude 模型 |
| **DeepSeek** | https://platform.deepseek.com/ | 国产，性价比高 |
| **Google** | https://aistudio.google.com/app/apikey | Gemini 模型 |
| **Moonshot** | https://platform.moonshot.cn/ | Kimi 智能助手 |
| **Azure OpenAI** | https://portal.azure.com/ | 企业级服务 |

#### 4. 重启服务

```cmd
cd E:\SmartBoBo
启动.cmd
```

#### 5. 在 Web 界面选择模型

1. 访问 http://127.0.0.1:7070
2. 点击 **设置** → **模型**
3. 在模型列表中选择你想要的模型：
   - OpenAI: `gpt-4o`, `gpt-4-turbo`, `gpt-3.5-turbo`
   - Anthropic: `claude-3-5-sonnet`, `claude-3-opus`
   - DeepSeek: `deepseek-v4-flash`, `deepseek-v4-pro`
   - Google: `gemini-1.5-pro`, `gemini-2.0-flash`
   - Moonshot: `moonshot-v1-8k`, `moonshot-v1-32k`

## 方案三：使用本地部署的模型（高级）

### 适用场景
- 你有本地部署的 OpenAI 兼容 API 服务
- 你想使用 Ollama、vLLM、LM Studio 等本地模型

### 配置步骤

#### 1. 编辑 `cordis.yml`

```yaml
- id: llm
  name: '@deepseek-ai/dsh-llm-pi-ai'
  config:
    providers:
      # 本地部署的 OpenAI 兼容服务
      local-llm:
        displayName: 本地模型
        apiKeyEnv: LOCAL_API_KEY
        api: openai-completions
        baseURL: http://localhost:11434/v1  # Ollama 示例
        models:
          - id: llama3.1
            name: Llama 3.1
            contextWindow: 128000
          - id: qwen2.5
            name: Qwen 2.5
            contextWindow: 32000
```

#### 2. 编辑 `.env`

```env
# 本地服务可以用任意非空字符串作为 Key
LOCAL_API_KEY=not-needed
```

#### 3. 重启并验证

```cmd
cd E:\SmartBoBo
启动.cmd
```

## 常见问题排查

### 1. 切换适配器后模型列表为空

**检查项：**
- 确认 `cordis.yml` 中 `llm-pi-ai` 适配器已启用
- 确认 `.env` 中至少有一个 API Key 已配置
- 重启服务后刷新浏览器

### 2. 某个模型无法使用

**可能原因：**
- API Key 无效或过期
- 该模型不在你的订阅范围内
- 网络连接问题

**排查方法：**
```bash
# 测试 API Key 是否有效（以 OpenAI 为例）
curl https://api.openai.com/v1/models \
  -H "Authorization: Bearer $OPENAI_API_KEY"
```

### 3. Key 格式验证

**PowerShell 验证脚本：**
```powershell
function Test-ApiKey {
    param([string]$key)
    if ($key -match '^[\x21-\x7E]+$') {
        Write-Host "✅ Key 格式正确" -ForegroundColor Green
    } else {
        Write-Host "❌ Key 包含非法字符" -ForegroundColor Red
    }
}

Test-ApiKey "sk-你的 Key"
```

### 4. 查看日志确认配置加载

启动后查看控制台输出，确认：
- ✅ `llm-pi-ai: registered provider routes: openai, anthropic, deepseek...`
- ❌ 没有 `MISSING_CREDENTIAL` 或 `INVALID_CREDENTIAL` 错误

## 技术说明

### 适配器对比

| 特性 | `llm-deepseek` | `llm-pi-ai` |
|------|---------------|-------------|
| 支持的模型 | 仅 DeepSeek | 多提供商 |
| 配置复杂度 | 简单 | 中等 |
| 灵活性 | 低 | 高 |
| 推荐场景 | 只用 DeepSeek | 多模型切换 |

### 凭证解析优先级

```
请求到达 → 
  1. 检查 ctx.credentials 服务（Web 界面存储）→ 
  2. 检查 .env 文件 → 
  3. 检查进程环境变量 → 
  4. 抛出 MISSING_CREDENTIAL 错误
```

### 代码位置参考

- DeepSeek 适配器：`dsh/packages/llm/llm-deepseek/src/index.ts`
- Pi-AI 适配器：`dsh/packages/llm/llm-pi-ai/src/index.ts`
- 凭证本地存储：`dsh/packages/credentials/credentials-local/src/index.ts`
- API Key 校验：`dsh/packages/llm/llm/src/api-key.ts`
