## 一、问题回顾

### 用户遇到的错误

**错误 1：**
```
llm-deepseek: no API key for provider route "deepseek-official"
```

**错误 2：**
```
llm-deepseek: the API key resolved from DEEPSEEK_API_KEY contains characters 
no HTTP header can carry
```

### 根本原因

1. `.env` 文件不存在
2. API Key 格式包含非法字符（中文、空格等）
3. 默认适配器仅支持 DeepSeek 单模型
4. 用户混淆了 OpenCode Go Key 和 DeepSeek Key

## 四、用户后续操作指南

### 快速开始（3 步）

1. **获取 API Key**
   - 访问：https://platform.deepseek.com/
   - 注册并创建 API Key

2. **配置 .env**
   ```
   编辑：E:\SmartBoBo\dsh\.env
   修改：DEEPSEEK_API_KEY=sk-你的真实 Key
   ```

3. **重启服务**
   ```cmd
   cd E:\SmartBoBo
   启动.cmd
   ```

### 使用其他模型

如需使用 GPT-4、Claude 等模型：

1. 在 `.env` 中配置对应 Key
2. 重启服务
3. 在 Web 界面选择模型

详细步骤见：`docs/说明文档/功能实现/10-API-Key 配置与多模型支持完整指南.md`

## 五、技术细节

### 架构变更

**原架构：**
```
用户 → Web 界面 → llm-deepseek → DeepSeek API
```

**新架构：**
```
用户 → Web 界面 → llm-pi-ai → 多模型路由 → 
    ├─ DeepSeek API
    ├─ OpenAI API
    ├─ Anthropic API
    ├─ Google API
    └─ Moonshot API
```

### 凭证解析流程

```
请求到达
    ↓
ctx.credentials 服务（Web 界面存储）
    ↓ (未找到)
.env 文件（启动环境快照）
    ↓ (未找到)
进程环境变量
    ↓ (未找到)
MISSING_CREDENTIAL 错误
```

### 配置优先级

```yaml
# cordis.yml 配置优先级
providers:
  deepseek:     # 优先级 1（默认启用）
  openai:       # 优先级 2（需配置 Key）
  anthropic:    # 优先级 3（需配置 Key）
  google:       # 优先级 4（需配置 Key）
  moonshot:     # 优先级 5（需配置 Key）
```

## 七、风险与注意事项

### 潜在风险

1. **配置不兼容**
   - 风险：旧配置可能影响新适配器
   - 缓解：已保留 DeepSeek 配置，向后兼容

2. **API Key 泄露**
   - 风险：`.env` 文件包含敏感信息
   - 缓解：已在 `.gitignore` 中排除该文件

3. **模型切换失败**
   - 风险：某些模型可能需要额外配置
   - 缓解：文档中提供了详细排查步骤

### 注意事项

1. **修改 .env 后必须重启服务**
2. **API Key 格式必须严格符合要求**
3. **不同模型的 API Key 不能混用**
4. **Web 界面缓存可能需要强制刷新（Ctrl+F5）**
