## 二、你仍需手动执行的步骤

### 2.1 安装 Node 依赖并构建（在 `BoBo/dsh` 内）

```bash
cd <项目根>/dsh
node -v        # 需 ^22.19 或 >=24；pnpm -v 需 9+
pnpm install
pnpm run build           # = build:lib（tsc -b + tsdown）+ build:web（前端）
```

> 构建新插件**不需要**单独 filter build（原指南错误）。根 `pnpm run build:lib` 的
> `tsc -b tsconfig.host.json` 会编译 `references` 里的 `packages/acquisition/tool-acquisition`
> （我已登记），根 tsdown 的 workspace glob 会自动把它的 `lib/` 打包进 bundle。
> 若只想增量编译 host 面：`pnpm run build:lib:host`。

### 2.2 配置 LLM Key

在 `<项目根>/dsh` 根目录建 `.env`（**勿提交 git**）：

```env
DEEPSEEK_API_KEY=你的Key
```

### 2.3 用 uv 建 Python 虚拟环境并装采集引擎

```bash
cd <项目根>
uv sync                                # 按 pyproject.toml 一键创建 .venv 并装好全部依赖
# 说明：scrapling/crawl4ai 以本地路径依赖引入（等效 editable），camoufox 从 PyPI 安装
```

### 2.4 直接测试 Python 脚本（独立验证引擎可用）

```bash

uv run python scripts/run_crawl4ai.py   --url https://example.com --out data/test_crawl4ai.json
```

### 2.5 启动 Web UI（bobo）

```bash
cd <项目根>/dsh
```

浏览器打开 **http://127.0.0.1:7070**。

## 三、生成文件的要点说明（为什么这样写）

### 3.1 `src/index.ts`（crawl_fetch）

对照真实 `defineTool` API 修正的关键点：

- `import z from '@deepseek-ai/schemastery'`（**不是** dsh-schemastery）。
- `Config: z<Config> = z.object({ ... default ... })`，不用 `{}` 占位。
- 可选项字段（engine/selector/outFile）**省略 `required`**，不写 `false`。
- `execute` 抛错即 `isError`，无需手动标记。
- `output.render` 返回 `ContentBlock[]`（`[{ type: 'text', text }]`）。
- 通过 `child_process` 调 `scripts/run_<engine>.py`，结果从 stdout 解析、写本地 `data/`。

### 3.2 `scripts/run_scrapling.py`

替换了两个不存在 API：
- `page.css_first(sel)` → `page.css(sel).first`（取首个匹配；无匹配时 `.first` 为 `None`，需判空）。
- `page.save_html(...)` → 手动 `open(...).write(page.html_content)`。

### 3.3 `packages/bobo/cordis.patch.yml` + `patch/web-acquisition.yml`

- 端口：`- id: webserver` + **完整** `config`（host + port）。
- 注入：**`- insert:`** 包裹 `tool-acquisition` 行，并把 `config` 改为**可移植**写法。
- **可移植化（推荐做法，当前已采用）**：插件 `name` 用**裸包名**
  `@deepseek-ai/dsh-tool-acquisition`，并把它声明进 `apps/cli/package.json` 的
  `dependencies`（`workspace:^`，与官方 `@deepseek-ai/dsh-tool-bash` 等一致）。
  这样启动时 dsh 的 `healProfilesModuleFallback` 会把它自动 link 到
  `~/.dsh/profiles/node_modules/`，任意机器/平台都能解析——**不再依赖写死的
  `file:` URL 绝对路径**。
- `config` 里 `pythonBin`/`scriptsDir` 用 `!!js` 表达式 + 环境变量 `BOBO_ROOT`
  （由 `启动.cmd`/`启动.sh` 自动设置）推导 `.venv` 与 `scripts` 路径，Windows /
  Linux / macOS 通用。
- **历史坑（已不适用）**：早期 host 层 `--patch` 裸包名会从用户 profile 目录
  `~/.dsh/profiles/web/` 向上找 node_modules，找不到 App workspace 里的自定义包，
  报 `ERR_MODULE_NOT_FOUND`，只能退而用 `file:` URL。该问题现已通过把自定义包加入
  `apps/cli` dependency closure 解决，`name` 使用裸包名即可。

### 3.4 浏览器默认引擎：camoufox（用户决策）

- 默认采集浏览器为 **camoufox**（抗检测，基于 Firefox），插件 `crawl_fetch`
  `engine` 默认值为 `camoufox`；可用 `scrapling` / `crawl4ai` 手动切换。
- `scripts/run_camoufox.py` 用 `AsyncCamoufox(headless=True, exclude_addons=[DefaultAddons.UBO])`：
  - `headless=True` 无头采集、不弹窗；
  - 排除 UBO 扩展：该扩展默认从 addons.mozilla.org 下载，失败会导致启动时
    `confirm_paths` 报 `manifest.json is missing`。
- camoufox 浏览器内核需先 `python -m camoufox fetch`（从 GitHub Releases 下载；
  若匿名 API 被限流，设 `GITHUB_TOKEN` 相关环境变量可突破）。
- 备选：playwright/patchright chromium（`python -m playwright install chromium`）
  已装好，作为 fallback 引擎。

## 五、如何新增采集能力（插件化扩展点，修订后）

与官方工具包一致的套路，每个能力 = 一个独立工具插件：

1. 在 `packages/<组>/tool-<能力>/` 新建（复刻 `tool-acquisition` 的 package.json / tsconfig / src）。
2. 用 `defineTool` 定义新工具（如 `crawl_batch`、`crawl_login`），`ctx.tools.register(...)`。
3. 对应加一个 `scripts/run_<能力>.py`。
4. **把 `{ "path": "./packages/<组>/tool-<能力>" }` 加进 `tsconfig.host.json` 的 `references`**（关键步骤）。
5. 在装配 patch 里加一条 **`- insert:`** 记录。
6. 根 `pnpm run build:lib` + 重启。

> 新增工具的包 `version` 必须等于根版本 `0.1.0-rc.7`；`@deepseek-ai/cordis` 需同时是
> peer 与 dev 依赖；`files` 需含 `lib/invariant.js` 等（对齐 `check-workspace-constraints`）。
